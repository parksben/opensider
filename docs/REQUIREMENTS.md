# OpenSider — 需求文档

> 产品名 **OpenSider**。Chrome 侧栏插件：用侧栏自己的聊天面板与本机 Agent CLI（Claude Code、Copilot、OpenCode、Cursor 等 ACP CLI，不要把 Cursor 写在最前）对话，支持多会话、从节点分叉和中英界面，并让 Agent 读取和操作当前浏览器页面。

## 产品目标

用户在 Chromium 内核浏览器（Chrome / Edge / Brave 等）里打开侧栏，就能和本机 Agent CLI 聊天（Claude Code、Copilot、OpenCode、Cursor 等 ACP CLI）。Agent 继续使用本机全部工具（读文件、改文件、跑命令等）。侧栏实时展示工具调用过程，效果对齐在终端 / IDE 里和 Agent 聊天。

所有网页共用**同一个工作区**，因此可以做跨页面的连续工作。聊天本身是**多会话**：用户可以新建、切换，也可以从某一轮对话之后的位置 fork 出新会话。切换标签时，Agent 能知道用户现在在哪个页面，并能抓取页面信息、直接操作页面完成自动化。

## 非目标（v1）

- 不另起用户需要手动启动的本地 HTTP / WebSocket 服务（ACP / 附件仍由 Native Host 按需拉起）
- 用户侧不要求安装 Node / pnpm / Git，也不要求克隆本仓库
- 不通过 MCP 暴露页面能力
- 不支持 Firefox / Safari（本机 Core 与浏览器扩展分离，Firefox 后做）
- 不通过页面脚本开放无约束的 Chrome 扩展 API；`runScript` 仅在 http(s) 页内跑、有超时与结果大小限制
- 不把聊天同步到云端
- 不上架 Chrome Web Store。扩展只以 `extension.zip` 分发，用户解压后用开发者模式「加载已解压的扩展程序」（不走商店，不发 CRX）
- 不接入 Claude Cowork（没有 CLI / ACP）

## 用户可见行为

### 安装与连接

1. 用户完成本机要使用的 Agent CLI 登录（Cursor `agent login`、Copilot `copilot login` 等）。不必装 Node。
2. **使用者主路径**（README 只写这四步）：从 GitHub [`releases/latest`](https://github.com/parksben/opensider/releases/latest) 下载 `extension.zip` 并在本机解压 → 在 Chrome / Edge / Brave 打开开发者模式、「加载已解压的扩展程序」、指向解压出的文件夹 → 点工具栏 OpenSider 图标打开侧栏 → 按侧栏提示把扩展连上本机 Agent（缺桥接时侧栏才给出安装命令），连上后即可开聊。不要把 CRX 当作安装路径，也不要在 README 把一行壳 / SHA256 / Host 二进制下载写成主流程。开发加载 `packages/extension/dist` 只写在 DEVELOPMENT.md。`opensider install`（由侧栏那行命令拉起）会探测本机 Claude Code：若已装且缺少 ACP 适配器，就把 `@agentclientprotocol/claude-agent-acp` 装进 `~/.opensider/runtime/claude-acp` 并校验。交互式 `claude` 本身仍不是 ACP。没装 Claude 则跳过；没有 Node 18+（npm / pnpm / bun）只提示，不让整次 Host 安装失败。Native Host 由浏览器按需拉起，不是常驻服务；可执行文件在 `~/.opensider/runtime/opensider`。安装壳仍可能把扩展解到 `~/.opensider/extension`，但使用者主路径是自己解压的 zip 目录。
3. **桥接未注册**：侧栏打开后若 `connectNative` 报找不到 Host，内容区居中提示：macOS / Linux「请复制下方脚本到终端/命令行中执行，完成后即可连接本地 Agent」（英：Copy the script below and run it in a terminal. When it finishes, you can connect to the local Agent）；Windows「请复制下方脚本到 PowerShell 中执行（不要用命令提示符），完成后即可连接本地 Agent」（英：Copy the script below and run it in PowerShell, not Command Prompt. When it finishes, you can connect to the local Agent）。下面是按浏览器 UA 选好的那一行脚本，可复制。Service Worker 约每 1–2s 重试连接；用户跑完脚本后**不必刷新扩展**，提示消失，进入 Agent 列表。Host 已安装但进程崩了只走重连，不再铺安装脚本。
4. **连接状态机**（桥接已注册）：侧栏只能走 `missing` → `starting` → `idle` / `ready`，或落到可见的 `error`。**禁止永远停在 starting**：Host 必须立刻应答 `hello` / `status`（先报 starting，CLI 探测在后台做）；探测有总时限，不能卡住 Native Messaging 读循环。若约 10s 还停在 starting，Service Worker 改报 `error`，文案指向 `~/.opensider/host.log`（扩展 ID / Host 名仍附上）。**「没有找到可用的 ACP CLI」只在探测已经完成且名单为空时出现**；Host 还在 starting、看门狗超时、或还没收到 `agents` 时，只说明连接/启动失败并给重试，不能假装本机没装 CLI。已收到非空 `agents` 就画名单，即使随后有一条 starting 超时。点顶栏「重连 / Connection」必须真正拆掉旧 Native 端口再连，不能因为上一次探测没结束就空转。从 Node Host / 旧目录迁过来的 `~/.opensider`（`PickFiles.app`、旧 `session.json`、`runtime/packages` 等）可能不兼容，开发时可备份后重新 `pnpm install-host` 重建。
5. **首次选择 Agent**（桥接已就绪、本机还没有完成过引导）：Host 探测本机已安装、且能用 ACP 握手的 CLI（不限于内置名单：已知启动方式 + 本机 PATH + nvm / npm-global / bun / `~/.opencode/bin` 等版本管理目录 + ACP Registry）。Chrome 拉起 Native Host 时 PATH 很瘦，不能只搜 `/usr/bin`，否则会漏掉装在 nvm 里的 Copilot 等 CLI。探测只用来列名单：二进制在即可列入，短超时握手失败也保留；真正连接再走完整握手。**Claude Code 的交互式 `claude` 本身不是 ACP**，探测的是 `claude-agent-acp`（`@agentclientprotocol/claude-agent-acp`）；只装了 `claude` 不会出现在名单里。`opensider install` 若发现 Claude Code 但适配器缺失，会自动装到 `~/.opensider/runtime/claude-acp` 并校验，装好后探测即可列入；没有 Node 只提示，不失败。重新跑一次 OpenSider 安装，或用 `claude` 登录，即可补上。引导区相对标题栏下方的内容区垂直居中。不画 CLI logo（本机没有产品标）。提示「点击 Agent 以开始连接」，下面是一排较大的纯文本按钮，点哪家就连哪家，不要再加确认钮；按钮有和别处一样的涟漪。探测尚未完成时转圈「正在查找本机 Agent CLI」，不要先甩一张空名单。连接若超过约 300ms，展示分步进度（解析 / 拉起 / 握手 / 鉴权 / 会话 / 模型）。进度条文案同一行最右侧是纯文本「取消 / Cancel」（不要 emoji）。进行中或卡住都可以取消**这一次**连接，但已经 `ready` 的连接不能用这个按钮拆掉。取消后回到**取消前**的状态：若之前已连上另一家 Agent，保持那一家（旧进程尽量不停，必要时再握手）；若之前没有已连接的 Agent，回到名单 / 未连接，不要停在新一家的半连接或失败态。成功后进入聊天。之后顶栏左上角是 Agent 下拉（纯文本 + 名），可换家；下拉必须浮在消息之上，点得到。换 Agent 时同一套进度条和取消钮出现在顶栏进度区（状态文案「4/6 · Signing in」右侧）。模型列表跟当前 Agent 的 `configOptions` / `session.models` / 其 list 命令走（Cursor：`agent models`；OpenCode：`opencode models` 的 `provider/model` 行，连上后若会话里还没有名单再拉一次）。只展示 Host 真正拿到的条目，不编一份假目录。Copilot 若 CAPI 名单为空，用它 CLI 内置的公开模型表兜底。**只有确认名单为空才藏下拉**，不能因为 `ready` 比模型列表先到就留一个空槽。换 Agent **不丢**本机会话：历史仍是侧栏自己的消息；老会话用新 Agent 继续聊时，把本地前文交给新的 ACP 会话。Gemini 若报 `EACCES` 写 `~/.gemini`，是本机目录属主不对（常见于曾经 `sudo` 装过），不是侧栏协议实现错了，错误文案要写明 `sudo chown -R "$(whoami)" ~/.gemini`。macOS 切 Agent 时若弹出「未打开 `.xxxx.node` / Apple 无法验证」的 Gatekeeper 对话框，那是本机 CLI 启动时加载或解到临时目录的 **未公证 native addon**，不是侧栏在拷贝或解压二进制；终端里直接跑同一条命令也可能出现。已知：**OpenCode 官方二进制（含最新 `~/.opencode/bin/opencode`）仍是 adhoc/linker-signed，官方重装不能变成 Apple 公证**；**Gemini**（`@google/gemini-cli`）和 **Claude ACP**（`claude-agent-acp` / `@agentclientprotocol/claude-agent-acp`）是 npm 脚本，附带 adhoc `.node`（如 `pty.node` / `keytar.node`），Apple 无法公证这类解包 addon。**GitHub Copilot 官方 Homebrew cask**（`brew install --cask copilot-cli` → `/opt/homebrew/bin/copilot`）是 GitHub Developer ID + 公证的 Mach-O，OpenSider 会搜到；npm 版 `@github/copilot` 仍带未公证 addon。Homebrew 的 `gemini-cli` formula 已弃用，替代品 `antigravity-cli`（`agy`）**不是** OpenSider 探测的 `gemini`。不要点「移到废纸篓」（会拆掉 CLI 自己的 addon）。应点「完成」，再到系统设置 → 隐私与安全性允许该文件。OpenSider 不去用户 CLI 安装上的隔离属性。
6. 点击工具栏图标打开 Side Panel。顶栏从左到右：左侧是 **Agent 下拉**（已连接时），未连接时才是连接状态（启动中 / 离线 / 出错）；**宽度足够时会话标题绝对居中**，单行省略，只展示、不可在顶栏改名；**最右侧只留一个**抽屉按钮：关闭时 Lucide `ChevronsLeft`（向左双箭头，打开抽屉），展开后 Lucide `ChevronsRight`（向右双箭头，收起）。tooltip 为「展开 / Expand」与「收起 / Collapse」，不要再写历史会话 / Past chats。顶栏不再放开关灯、语言切换，「新会话」也不在顶栏。宽栏时顶栏只有三块：左 Agent 下拉（或未连接状态）、中会话标题、右抽屉钮。**会话主体**（顶栏+消息+输入，不含右侧抽屉）宽度 **小于 348px** 时进入窄布局：隐藏 Agent 下拉，标题改为居左；抽屉钮保留。窄布局由主体宽度决定，无论是拖 Chrome 侧栏还是打开/拖宽会话抽屉把主体挤窄，都要立刻切换。顶栏不再放当前页 favicon。offline 时状态旁有「重连 / Connection」（旋转箭头 icon 已表示重试，英文不再写 Retry）。不再单独铺一条当前页 banner。不放插件名和 slogan。未连接时说明原因。重连必须真正重连 Native Host，不能因为端口已断开就静默失败。两套主题的正文、次要文案与背景对比度都要够读，不能在某一主题下糊成一团。全栏默认字重 **400**，标题 / 强调 / Markdown 加粗一律 **500**，不用更重的 600/700。
7. 顶栏标题只展示、不可点击改名；重命名只在右侧会话列表卡片上进行。标题不设固定字数或固定像素上限；被右侧操作区挤住才单行省略，hover 用原生 `title` 看全文。**宽栏居中**时左右各留 **32px** 安全距（避开 Agent 与抽屉钮），「新会话」/「New Chat」也要看得见，不能因为居中槽位塌成 0 宽而消失。**窄栏居左**时标题从状态条右侧（没有则顶栏左缘）起排。**未命名会话不写默认标题进数据**（`title` 保持空）；顶栏和会话列表只在展示时用「新会话」/「New Chat」。标题为空，或仍是「新会话」/「New Chat」/「New chat」时，用户发出一条消息后用该条正文首行（没有正文则用附件名）作为标题，不再按字数截断。点最右侧侧栏按钮打开**右侧抽屉**（不是居中模态、没有遮罩）：抽屉推出时把整栏主体（顶栏、消息、输入框）往左挤。抽屉左缘可拖，改变宽度时同样挤压主体。展开/收起与宽度写入本机。抽屉顶部两个 tab：「会话 / Sessions」（左 Lucide `MessageSquare`）和「设置 / Settings」（左 Lucide `Settings`），只这两个，不要第三栏。**会话** tab 自上而下：全宽筛选（按标题不区分大小写；中文占位「输入关键字以筛选会话...」，英「Filter sessions...」，输入框上下内边距各比原先多 8px）→ 全宽「新会话」按钮（Lucide `Plus` + 文案）→ 按时间聚合的会话列表。**设置** tab 放主题和语言，各是一行带前缀的下拉：左边灰色 Prefix（中「主题」「语言」，英 Theme / Language；深色用 `--muted`，浅色同样走 `--muted`，保证比正文浅一档），右边是当前选项，点开下拉选。主题三项文案：浅色模式 / 深色模式 / 跟随设备（英 Light / Dark / Device），下拉项左侧保留 `Sun` / `Moon` / `Monitor`；语言两项文案不随界面语言变：中文项一律「简体中文」，英文项一律 English。不要再做成顶栏 icon 循环切换。分组从左标题（紧贴右侧 Lucide 展开/收起箭头：展开 `ChevronDown`、收起 `ChevronRight`）、右侧该组条数；整行可点，切换展开收起；组头上下各比原先多 4px 内边距。若有置顶则最顶是「置顶 / Pinned」；其余未置顶按本地日历分成「今天 / Today」「最近 7 天 / Last 7 days」「更早 / Older」；空组不出现。组内按 `updatedAt` 倒序。卡片上下内边距各比原先多 8px。卡片左侧空闲是小圆点，进行中换成六点盲文字符循环 spin，不再在标题旁转圈。标题与置顶 / 重命名 / 删除三个按钮同一行垂直居中；按钮仅鼠标悬停该卡片时出现，移出后从布局里拿掉，标题占满剩余宽度、单行省略。点会话只切换、不关抽屉；Esc（不在输入框里时）或再点顶栏按钮收起。上下键循环高亮并滚入视口，回车切换。语言和主题只在抽屉「设置」tab 里用下拉切换，不再占用顶栏。
8. 连接成功后，Host 按当前选中的 Agent Profile 拉起对应 ACP 进程（Cursor 仍是 `agent acp`，其它见 TECH_DESIGN），复用该 CLI 已有登录。关掉再打开侧栏时，应回放最近一次连接状态，而不是一直停在离线。侧栏与 Service Worker 之间的端口断开时，不得抛未捕获异常（Chrome 扩展页里那种 `disconnected port object`），并应自动重连；不要停在「Lost connection to the extension service worker」就不再试。
9. 用户发送后，侧栏立刻出现用户气泡，输入框描边进入进行中动效。进行中发送钮仍可点（入队），旁边保留停止钮。不再另起一行「Agent is working」转圈。离线时发送会留下可见错误，而不是没有任何反馈。

### 聊天

1. 侧栏是唯一的对话入口。消息列表、输入框、进行中状态由侧栏自己渲染，不依赖 assistant-ui 的 runtime 选择器。空会话在消息区垂直居中放产品 logo（与扩展图标同一套，约 120px，透明度 30%，并用 CSS 把饱和度降到约 20%）和一行淡灰提示：发送消息，开始与 Agent 就网页内容聊天（英：Send a message to start chatting with Agent about this page）。Logo 和这行提示都禁止鼠标划词选中。提示两侧各留约 200px，宽度够就不要换行；侧栏太窄再折行。
2. 用户气泡宽度随内容收缩，最大不超过消息列表区域总宽的 80%，靠右。用户发送消息后，该气泡固定在这一轮的位置，本机 Agent 的正文和工具调用只追加在它后面，不得写进上一轮回复里把这条气泡往下挤。输入框占位固定提示「回车发送 · Shift+回车换行 · 输入@可引用内容」（英：Enter to send · Shift+Enter for a new line · Type @ to mention），不随连接状态变化。未进行中时输入框获得焦点，四条边框都轻微提亮（深色略亮、浅色略深，对比不要强），过渡约 160ms，不要拖到接近半秒。占位只是空态提示，不是可编辑内容：删光正文和芯片后，光标停在内容区最前面，不能停在占位文案后面。文本输入区是可混排芯片的富文本（不是纯 textarea）：默认高度为 2 行正文；内容变多时跟着长高，满 10 行后出现滚动，并始终把光标所在行滚进可视区。当前会话进行中时，输入框描边换成 Chrome Logo 四色圆锥渐变（红 `#EA4335`、黄 `#FBBC05`、绿 `#34A853`、蓝 `#4285F4`），先过渡铺满 360°，再以 4 秒一圈持续旋转；结束后整圈淡出，回到原来的细线，不要把描边收起来。**会话主体宽度小于 348px** 时，输入栏只隐藏权限模式下拉，回形针 / 拾取 / `@` 仍展示，右侧仍留模型选择与发送 / 停止。输入区和工具栏分两行：第二行左侧从左到右是回形针（添加附件）、拾取元素、`@`（提及）、权限模式下拉（四档：默认权限 / 允许文件修改 / 允许工具调用 / 允许一切操作；每项模式名 + 灰色小字：用户确认后方可调用工具 / 允许工作区内文件修改，执行命令、联网操作仍需确认 / 直接执行工具调用，问题和计划仍需确认 / 工具、问题、计划无需确认。英：Ask every time / Allow workspace edits / Auto-run tools / Allow all；灰色小字 Confirm each tool / Workspace file edits skip confirmation; commands and network still ask / Tools skip confirmation; questions and plans still need a click / Don't ask about tools, questions, or plans），右侧是模型选择和发送钮。工具栏始终单行：宽度不够时（例如进行中多出停止钮），权限模式触发钮文案先单行省略（不换行），该控件有最小宽度（约 5rem，够放下图标和省略号）；触达该最小宽度之后才允许挤压右侧模型选择，其触发钮文案同样单行省略。省略只作用在触发钮文字上，**不得**把权限/模型下拉的弹出层裁掉；点触发钮必须能弹出完整菜单（与模型下拉同一套可见行为）。下拉菜单项仍显示全文。发送 / 停止图标钮不参与挤压。回形针、拾取和 `@` 三个图标按钮之间间距为 0，不留缝。发送钮用 Lucide 小飞机纯图标；进行中停止钮与发送钮并存（发送入队）。所有纯图标按钮都有 tooltip，须完整落在侧栏视口内并与边缘留出安全距离，不得被裁切。除顶栏按钮外，其余按钮（输入区、新建会话、会话卡片操作、Agent 回复下的 fork / 重新生成、权限条等）hover 为半透明覆盖（深色偏白、浅色偏黑），点击有 CSS 涟漪。历史会话在右侧抽屉里打开，不遮罩。
3. 回形针要本机绝对路径，不能用页面 `<input type=file>`。系统种类用浏览器 UA（优先 `userAgentData.platform === "macOS"`）。macOS：直接开一个可同时多选文件和文件夹的系统框。Windows / Linux 的系统框不能混选：点击回形针后在按钮上方立刻弹出下拉（不是全栏模态），两项为「选择多个文件 / 选择多个文件夹」，再开对应系统多选框；两种都要则再点回形针。未连上 Host 时回形针留下可见错误，不能静默没反应。Host 按 UI 传来的 mode 去 `opensider pick`（独立进程才能把面板拉到前台）。输入框支持直接粘贴截图（或剪贴板里的图片）：粘贴后进入同一套附件芯片，随这条消息一起发出；同一张图只生成一个芯片，不要因为剪贴板同时带 files / items 就写两份。未连上时留下可见错误，不能只把图片糊进文本框。拾取按钮用光标 icon：点后**整栏**立刻被带背景模糊的遮罩盖住，提示叠在遮罩上；点遮罩不取消。网页进入拾取态（十字光标、悬停高亮），再点一下即拾取。遮罩和提示只在拾取完成或按 Esc 后消失。已打开的 http(s) 页即使还没注入过内容脚本，点拾取也会补上，不必先刷新。YouTube / youtu.be 视频页（含从首页点进 `/watch` 的 SPA 跳转）同样要能进入拾取：至少能点到标题、评论、相关视频等页面骨架；播放器若在 iframe 里，点不到内部控件也可以，但不能把整页当成系统页拒掉，也不能点了没反应。补注入失败必须留下可见错误。选中后在文本框上方以芯片展示。文件芯片和拾取元素芯片同一套尺寸：最大宽度约 200px，超出省略，悬停用 title 看全文；图片 / 普通文件 / 文件夹 / 拾取元素用不同 lucide 图标；芯片右侧可删。从附件栏删掉某项后，正文里对应的 `@` 附件芯片也要拿掉，`@` 菜单不能再提到它。输入栏附件和用户气泡里的图片芯片可点：全栏弹出模态预览，遮罩约 2px 背景模糊，颜色跟侧栏 `--overlay` / `--panel` 走，不要另起白底灯箱。图相对视口绝对居中，按自身像素显示；太宽则等比缩小，左右各留视口宽度的 10%。预览要能放大、缩小、拖拽平移和复位（滚轮 / 捏合 / 拖拽 + 顶栏按钮）。顶栏用 lucide：`ZoomIn` / `ZoomOut` / `RotateCcw`（复位）/ `X`（关闭），tooltip 中英都要。点遮罩、点关闭或 Esc 退出；点图片本身不关，否则和拖拽打架。进行中仍可预览，不要因为气泡不能改历史就把图片点不了。Chrome 扩展页即使 CSP 写了 `file:` 也显示不了 `file://` 图，所以预览必须由 Host 读本机文件，再经 Native Messaging 分片回侧栏（单帧不超过 1MB），侧栏拼成 `blob:` 给 `<img>`。只预览用户已经挂上的图片附件路径，不接受任意 URL。加载中在正中转圈，不要静默失败；转完再露图。失败则居中显示「无法加载这张图片」（英 Couldn't load this image），句末不加句号。文件附件发给 Agent 的是本机绝对路径，不上传内容。元素附件带全局唯一 CSS Selector（等同 DevTools「复制 selector」），并说明这是用户在当前页拾取的节点，供 Agent 查看或操作。没有正文、只有附件时也可以发送。附件不写入本机历史。
4. `@` 按钮在拾取按钮右侧。点击后把光标移到输入区最前面并插入一个 `@`，同时打开提及菜单。菜单是跟着**当前光标**的弹出层，优先出现在光标上方，不得挡住正在输入的那一行；整层与侧栏视口四边保持 16px 安全距离，空间不够则缩短列表高度并内部滚动，不要贴边或画出界面。两个 tab：**标签页**（当前浏览器普通窗口里正在打开的标签，左 favicon、右标题；不缓存已关闭的历史标签）和 **附件**（只列当前输入栏里还未发送的附件芯片，左 kind 图标、右名称，样式对齐附件栏但不带关闭钮；不读、不写本机附件历史）。**菜单打开期间**，光标前 `@` 之后继续输入的内容即搜索词（不另起筛选框）；删光 `@` 或把光标移出该 `@` 触发区则关闭菜单。搜索不区分大小写：标签页匹配标题与 URL，附件匹配名称与路径；标题 / 名称优先于 URL / 路径排序；匹配字符在标题 / 名称上直接换成主题强调色（不要选中块底色）；无匹配项过滤掉，关键词越长列表越短。标签页按当前打开的 `tabId` 列出，同一 URL 开了多个就显示多条；关掉的标签立刻从列表消失。键盘：Tab / 左右键切菜单 tab；上下键在当前**筛选结果**里循环高亮，列表跟着滚到高亮项，到头再按则绕回另一端；回车只把高亮项插成芯片，**不得发送消息**；Esc 关闭。鼠标：可点 tab 和选项，同样只插入、不发送；点击不得让输入区失焦（mousedown 先记下选区，插入前再恢复）。选中项以芯片插入正文，替换光标前的 `@` 及紧跟的搜索词，和文字流式混排：芯片 DOM 两侧各补一个空格；插入点前面已经是空格则不再补左边，后面已经是空格则不再补右边。芯片高度必须等于所在行正文的行高（和划词选中时那块底色一样高），不得跟着芯片里的小字塌下去；内容相对这个行高容器垂直居中。容器右侧 padding 12px、左侧 8px。最大宽 200px、超出省略，悬停用 title 看全文。点击芯片不得把光标放进芯片内部，应落到该芯片后方；芯片容器内禁止划词选中。发出去的用户气泡用同一套芯片混排渲染。发给 Agent 的正文要把芯片反序列化成它能读懂的结构化说明（提及的标签页给 title / URL / tabId，提及的附件给路径或 selector），不能只剩一个看不懂的 `@`。
5. 未连上时不展示模型下拉。连上后只展示 Host 从该 Agent 的 list 命令（Cursor `agent models`、OpenCode `opencode models`）和 ACP `configOptions` / `session.models` 拉到的列表，不自己再塞选项。OpenCode 的名单常在会话起来之后才齐，侧栏不得把「ready 时列表还是空的」当成最终空名单；确认 CLI 与会话都没有模型后才藏下拉。列表顶部有一个固定筛选框（不随条目滚动，无边框 / outline），弹出后自动聚焦，按已加载的名称或 id 做不区分大小写的包含匹配；中文占位为「筛选...」。上下键在当前筛选结果里循环移动高亮（向下超出最后一条回到第一条，向上超出第一条落到最后一条），列表跟着滚到高亮项；回车切换到高亮模型。列表里若有 CLI 的 `auto`，下拉默认选中它（表示不指定，不发给 ACP）。用户后来选了具体模型才写入本机并作用到当前会话；下次打开若仍记得该模型则保持，否则回到 auto。
6. Agent 调用本地工具时，侧栏用灰色小字展示：左侧 lucide 图标标明 kind（读取 / 编辑 / 执行 / 搜索等），颜色与灰字一致，旁边是工具标题（路径或查询原文保留）。不要做成带边框的卡片。点开后往下展开，入参和返回分别展示：能 `JSON.parse` 的（或本身已是对象）递归拆成段落，不能解析的原文保留。最外层对象若只有一个 key，不显示该 key，只展示它的 value；多个 key 则每项一段，`key` 与 value 用全角冒号「：」连接。value 若还是 JSON 则同样往下拆，内层一律按 KV 段落输出（不再省略单 key）。每深一层，子段落 `padding-left` 增加 `1em`。转成段落后要去掉空行（连续换行压成单次换行，空白段不渲染）。内容最多约 5 行，超出才滚动；不足则盒子跟着内容变矮，不要写死高度。边缘渐变遮罩与过程区相同。进行中标题左侧只显示同色细转圈，不要和 kind 图标并排；转完再换成 kind 图标。标题右侧用全角冒号「：」接上最重要的参数（读取 / 编辑接路径，获取接 URL，执行接命令，搜索接查询），进行中拼上之后结束后也不要拿掉；二次打开历史会话时同样保持这串拼接，不要变回短标题。不要另起一行。整行（含左侧转圈或图标、右侧箭头）单行显示；箭头紧挨文案，不要一开始就居右，只有文案过长被省略时才被顶到行尾，不得折到下一行。流式进行中，若连续多段思考 / 工具中间没有正文，只保留最后一条占同一行，不要一条条往下堆；整轮结束后用户展开「此次执行」才把每一步平铺成各占一行。
7. Agent 请求权限时，默认「默认权限 / Ask every time」：每次 ACP `request_permission` 弹卡（允许一次 / 始终允许 / 拒绝），不自动放行写文件和执行命令。第二档「允许文件修改 / Allow workspace edits」：工作区 cwd 内的编辑/写入自动过，Shell、出网、出目录仍问；不是工作区内所有命令都自动过。第三档「允许工具调用 / Auto-run tools」：工具权限自动选始终允许（没有则允许一次），不再弹卡；不是任何指令都自动过。提问（`cursor/ask_question`）和计划审批（`cursor/create_plan`）前三档都要人点。第四档「允许一切操作 / Allow all」（id `unattended`）：真正无人值守——工具权限按第三档同样自动选始终允许（没有则允许一次），计划卡自动接受，提问卡按确定性规则自动答（每题选第一项；没有选项则交空答案），不把 HITL 卡留在输入框上方等人点。不要把第三档改名叫 Allow all。模式写入本机（`agentMode`）。切到允许工具调用时已弹出的权限卡立刻自动放行；切到允许文件修改只自动放行编辑类；切到允许一切操作时已弹出的权限 / 提问 / 计划卡立刻按上面规则消掉。切走允许一切操作后不再自动过。界面文案要像系统设置：标题短、说明一句、口语，不要翻译腔或营销句。
8. Agent 下发的提问、计划审批、todo 更新，在侧栏可见并可回应。权限 / 提问 / 计划卡片都落在输入框上方（不在输入框下面）；正文同样限高约 9.5 行。Agent 规划的 todo 也不挂在顶栏下，而是同样落在输入框上方：标题栏为「英文 Todo List / 中文 待办项 - 已完成/总数」（如 Todo List - 3/3、待办项 - 3/3），右侧是展开/收起箭头，点击整行标题即可折叠；完成项右侧用带圆圈的对勾 icon（Lucide `CircleCheck`）表示。用户收起后，下次 Agent 再规划出新的 todo（条目 id 或文案变化）时自动展开。新一轮任务一开始就清掉上一轮的 todo；Agent 再列出待办时整表覆盖，不得把上一轮条目并进来。思考过程也是灰色纯文本折叠（「思考 / Thinking」+ 紧挨着的箭头），去掉空行，点开后同样向下展开：最多约 5 行，超出才滚动，不足则贴内容高度，边缘渐变遮罩。Agent 回复里的 ` ```mermaid ` 围栏：`flowchart` / `graph` 用轻量 SVG（`@dagrejs/dagre` 布局，不引入 mermaid 包）画成图；其它类型或解析失败仍显示原来的代码块。不得往 `body` 挂报错 SVG。输入框打字不得让消息列表重跑图或抖动。GFM 表格要画出单元格边框，侧栏太窄时可横向滚动，不能只剩对齐的字。Agent 正文里的链接：若与当前浏览器标签页是同一域名（主机名忽略大小写，`www.` 视为同一站点），点击后在**当前标签**跳转，不要新开标签；域名对不上，或当前没有可用的 http(s) 标签，再新开标签。只处理 `http(s)`。按住修饰键点击一律新开标签，避免把侧栏自己导航走。一轮流式输出**结束之后**，只留下最后一段非思考、非工具调用的正文；思考、工具调用以及它们之前的内容全部折起。收起时是一行灰色纯文本，说明此次执行花了多久（如「此次执行用了 12 秒 / Worked for 12s」）；没有记下时长的旧消息只写「已执行 / Worked」。箭头紧挨文案，不要居整行右侧，也不要做成整行色块或按钮底。鼠标悬停某一行时，只在这一行文案旁出现向右箭头，不要把同条消息里其它工具 / 思考 / 过程行的箭头一起亮出来。整行都可点，但视觉上只是灰字加箭头；点开后箭头改为向下，过程**往下展开**，灰字那一行不要被顶走。过程区只设最大高度、内部可滚，内容不够高时盒子跟着变矮，不要写死高度，避免长过程把后面的正文顶出屏幕。滚动时用混合模式做边缘渐变：还没滚到顶则上方从不透明到透明，还没滚到底则下方从透明到不透明。再点折起。进行中不出现耗时行：连续思考 / 工具（中间无正文）只显示当前最后一条，方便看正在做哪一步。整轮结束后过程先收成耗时行；用户再展开时，这些步骤才按每条一行平铺。若这一轮只有正文、没有过程，就不出现这一行。
9. 用户可中断当前一轮。Cursor CLI 有时在一轮已经成功结束后，把内部流关闭 `RetriableError: WritableIterable is closed` 写成气泡正文，或把 `session/prompt` 收成错误。成功的一轮不得在气泡开头/末尾或顶栏错误条里露出这句；鉴权失败、进程崩溃、真实工具错误仍要可见。不得把 Agent 正文里任意 `Error:` 行都剥掉，只认这一条已知的可重试关流（或等价 ACP 错误），且本轮已经产出过正文或工具结果。
10. 用户可点击已发送的用户气泡，把正文和附件带回输入框修改。输入框顶部左侧提示「正在修改历史消息，重新发送后，该位置后的全部内容将重新生成」（英：Editing a past message. Resending will regenerate everything after this point.），右侧纯文本「取消修改 / Cancel edit」，用主题强调色（深色黄铜 / 浅色钢蓝），带 hover 和点击涟漪。重新发送后该条被替换，其后全部丢掉并重跑。进行中不可点气泡。
11. 当前会话一轮尚未结束时，用户再发送不立刻交给 Agent，而是进入该会话的消息队列。进行中仍可点回形针、拾取和 `@`，方便往队列里组消息。队列列在输入框上方：每行左侧是正文（过长省略），右侧依次是立即发送（Lucide `CornerDownLeft`，回车/换行）、编辑、删除。删除后这条永远不会发出。立即发送会打断当前这一轮，再把**这一条**发出去（不必等到排到队首）；其余队列项仍按原顺序接着跑。编辑把正文和附件带回输入框；输入框顶（队列下方）左侧提示「正在编辑队列消息，点击发送后会覆盖队列中对应的消息内容」（英：Editing a queued message. Sending will replace it in the queue.），右侧「取消编辑 / Cancel edit」。取消不改队列项。发送时若在改队列项则覆盖该项；否则在进行中入队、空闲则直接发。Agent 本轮结束后自动发出队列最前面一条，再等下一轮结束，直到清空。若用户正在改某条：改的是队首则等他改完点发送再发；改的不是队首则队首仍可按轮次发出。队列按会话分开，不写本机持久化。
12. 有消息后列表仍用 `flex-col-reverse` 做贴底滚动：发送和流式输出时自动跟随；用户往上翻则停止跟随；再滚回靠近底部（约 96px 内）则恢复跟随。内容还没撑满消息区时（空会话刚发出第一条、Agent 还没写很长），消息从**顶部**排，不要贴在输入框上方；只有正文把区域撑满后，旧消息才被顶上去。离开底部超过该距离时，输入框上方浮一层圆形「回到底部」按钮：绝对定位盖在消息上，不占一行、不把列表挤矮。贴底、刚离开几像素、或继续往底外弹性滚动时都不要出现；从底部往上滚时，距底未超过约 96px 保持隐藏，超过后稳定展示，不要先显后隐再显。水平相对输入区居中，上方留约 16px。直径约为原先 56px 的 0.7（约 39px）。默认半透明底 + 轻投影，好和底下的消息分开；hover 时不透明度升高；点击有涟漪。带 tooltip。
13. Agent 完成会落盘产物的任务后，须调用工作区工具 `reportArtifacts`，把本轮产物的本机绝对路径交给侧栏（路径优先 `outputs/...`）。输入框上方（Todo / 权限卡之下、消息队列之上）出现可展开/收起的产物列表：标题「产物 / Artifacts」加条数，点整行标题折叠。每一项左侧是按种类的 lucide 文件图标，中间是文件名（过长省略，悬停看完整路径），最右侧是「打开文件位置 / Show in folder」（仅该项 hover 时出现）。点后由 Host 用系统文件管理器打开所在文件夹并选中该文件（macOS `open -R`，Windows 资源管理器 `/select`，Linux `FileManager1.ShowItems`）。若该文件已经不在本机，Host 必须回明确错误（不能静默没反应）。侧栏立刻拿掉该项的打开按钮，换成不可点击的灰色小字「文件已失效 / File missing」（比 `--muted` 再淡一点，无 hover），并把失效记在这条会话产物上，关掉侧栏再打开或再 hover 都不得把按钮变回来。成功打开则保持原行为。同一会话再次调用 `reportArtifacts` **整表覆盖**，不追加，新列表没有失效标记。Agent 若复用同一个命令文件 id 再写一次，侧栏仍要收到这次覆盖，不能只认第一次。空列表不渲染。产物跟会话走，关掉侧栏再打开仍在；新建 / fork 的会话从空表开始。

### 工作区与会话

1. 所有页面共用一个工作区：`~/.opensider/workspace`。页面工具、快照、命令文件不随聊天会话切换。Host 每次启动 / 安装都会确保存在 `outputs/`（0755）。用户会打开的任务产物（html / pdf / md / 图片等）应写在 `outputs/`（相对工作区 cwd），不要落在工作区根目录和 `AGENTS.md`、`browser/` 混在一起。草稿、临时文件可以放别处。这是工作区约定，**不**拦截 Agent 的 Write / Shell。写完后仍须 `reportArtifacts`。
2. 聊天是多会话。侧栏可新建、切换、重命名、置顶、删除会话。会话卡片上有置顶、重命名和删除按钮，与标题同一行，仅 hover 时出现；置顶后进入列表最上方的「置顶」分组，取消置顶则回到按时间的分组。进行中的会话左侧用六点字符 spin 代替圆点。手动改过的标题不会被后续消息覆盖；空标题和默认的「新会话」/「New Chat」不算手改，发出消息后仍会换成首条正文的一行标题（不按字数截断）。删除前用非阻塞 popover 二次确认（不是 `window.confirm`、不铺全屏遮罩）。弹层锚在删除按钮旁，与视口四边保持 16px 安全距离，空间不够则翻边或缩短，标题过长省略。Esc / 点外面取消；确认后才真正删除。删掉当前会话会切到另一条；删光则自动新建一条。关掉侧栏或换标签不会自动新建。
3. 当前选中的会话、每个会话的标题和消息历史，关掉侧栏再打开仍然在。Host 重启后尽量 `session/load` 回对应的 ACP 会话；失败则新建 ACP 会话，界面历史仍保留，下一条用户消息会带上此前的摘要上下文。完整侧栏状态（语言、主题、权限模式、选中的 Agent/模型、会话列表与每条消息、抽屉开合与宽度、引导是否完成）除了写 `chrome.storage.local`，还要镜像到本机 `~/.opensider/ui-state.json`。卸载或刷新扩展会清掉 `chrome.storage`，**不得**因此丢掉会话：Host 连上后若本机镜像比扩展存储新（或扩展是空的），用镜像灌回侧栏。空状态不得覆盖已有镜像。ACP 工作区里的会话还在，但不得把 `session/load` 回放的整段 prompt 画成一条用户气泡。已经坍成一条的本地记录，打开时尽量按 `User:` / `Assistant:` 拆回多轮，并去掉 `[Current tab]` / fork 包装前缀。用户气泡和会话标题也不展示这行环境前缀。
4. 用户可从任意一轮 **Agent 回复** **fork**（用户气泡下不放）：原会话不动，新会话复制该回复及之前的消息，之后独立往下聊。不做 checkpoint。中文 tooltip 为「从此处复制新会话」，英文为 Fork from here。
5. Agent 回复底部一行只在 hover 时出现：左侧灰色字说明此内容由哪个模型生成（如「由 Auto 生成 / Generated by Auto」），右侧无边框 **复制**、Fork 与 **重新生成**（刷新 icon）。复制只写入这一轮可见正文的 Markdown，不含已折起的「此次执行 / Worked」过程（思考、工具调用、过程前的正文）。点复制成功后，Copy icon **原地**换成对勾（Lucide `Check`），约 1.5 秒再切回；成功反馈期间这一行保持可见，不必一直悬停。本轮还在流式输出时，最后一条回复上这一行无论是否 hover 都不出现，结束之后才可以。重新生成会丢掉该轮及之后的 Agent 回复，用同一条用户消息再跑一遍，不另开会话。中间轮次重跑会截掉后面的对话。中文 tooltip 为「复制 / 已复制 / 重新生成」，英文为 Copy / Copied / Regenerate。用户气泡上方间距是普通消息间距的两倍（24px），跟上一轮 Agent 回复拉开。
6. 多个会话可以同时跑不同任务。某一轮还在进行时，仍可新建会话或切到别的会话继续发；流式更新必须写回**发起这一轮的会话**，不得因为后来选中了别的会话而写错地方。切走之后，输入框的进行中态、停止钮和权限/提问/计划卡片只属于当前正在看的会话：回到那个会话才能看到并处理。对某个会话做 fork、重新生成或改历史再发时，只在**该会话自己**正在跑时拒绝。重命名随时可以。删除正在跑的会话会先取消这一轮再删。

### 语言

1. 界面只做中英两种。**首次安装**（本机还没有语言偏好）时跟浏览器 UI 语言：中文（`zh*`，含 zh-CN / zh-TW 等）用简体中文，否则英文。之后以用户在设置里选的为准，不要每次打开再去读浏览器。
2. 语言在右侧抽屉「设置」tab 用下拉切换 English / 中文。界面中英都不使用衬线体。
3. 语言选择写入本机，下次打开仍是上次的选择；打开侧栏第一帧就要用上次的语言（或首次安装时探测到的语言），不要先闪英文再切回去。
4. Agent 工作区说明（`AGENTS.md`）保持英文，不随界面语言切换。

### 主题

1. 界面有浅色、深色两套，另可跟随系统 `prefers-color-scheme`。**首次安装**（本机还没有主题偏好）时默认「跟随设备」，与浏览器外观设为跟随系统时一致；实际明暗跟 `prefers-color-scheme`（Chrome 的浅色 / 深色 / 设备都会反映到该查询）。之后以用户在设置里选的为准。
2. 主题和语言都在右侧抽屉「设置」tab 里用带灰色 Prefix 的下拉切换，不在顶栏循环点 icon。主题三项：浅色模式 / 深色模式 / 跟随设备（英 Light / Dark / Device）。
3. 主题选择写入本机，下次打开仍是上次的选择；打开侧栏第一帧就要用上次的主题（或首次安装时的跟随设备），不要先闪默认深色再切回去。跟随设备时系统改明暗，侧栏立刻跟着变。
4. 浅色是柔和、有层次的中性浅灰（浅灰画布 + 近白抬升面 + 钢蓝强调），不要暖黄纸色，也不要发脏的蓝灰底。正文、muted、链接/强调色、用户气泡、代码块在两套主题里都对背景保持足够对比，禁止浅色主题继续用深色专属的浅字或深底。

### 页面感知与操作

1. 浏览器**活动标签**一旦变化，扩展必须实时更新「当前页」：用户点击其它标签、关掉当前标签后浏览器激活另一张已打开的标签、窗口获得焦点、标签在窗口间移动 / 挂接 / 分离，或当前页 URL 变化。关掉当前标签时不得继续把已关闭的 tabId / URL 当作当前页。每次活动标签变化都要同时刷新工作区 `browser/current.json`（以及 `snapshot.md` / `interactive.md`）和 `browser/tabs.json`，好让下一条用户消息的 `[Current tab]` 行、侧栏页面状态、以及 Agent 读到的工作区文件都指向新的活动标签。同域链接点击仍按原规则在当前标签跳转，不另开标签；本条管的是标签身份 / 当前页，不是页内链接。
2. 侧栏不再用 banner 或顶栏 favicon 展示当前页标题与 URL。Agent 正在执行页面命令时，不要把该方法名挂在顶栏：它是工具调用提示，写进当前这一轮对话正文（和其它 tool-call 同一套灰字折叠），不是 Todo List。
3. 每条用户消息在发给 Agent 时附带一行当前页上下文（标题 + URL），界面里只显示用户自己输入的文字。
4. 内容脚本向页面注入白名单方法；批处理另可由 SW 执行 `runScript`。Agent 通过工作区命令文件调用，不走 MCP。扩展刚刷新、标签在注入前就打开、或页面（如 YouTube）在 `document_start` 之后内容脚本还在异步加载时，页面读取 / 操作 / 快照必须先补注入并等到页面 API 就绪，不能因为没有消息接收端就让 Agent 读到空的 `snapshot.md` / `interactive.md`，或只看到 Chrome 的 `Receiving end does not exist`。命令无论成败都要写出 `browser/results/<id>.json`；失败错误要能看懂（系统页、未注入、超时分开说）。
5. **读取**：元信息、正文、选区、链接、标题大纲、按选择器取文本 / 属性 / 值、列出匹配元素、判断元素是否存在。另可列出当前 Chrome 里所有普通窗口和标签（`tabId` / `windowId` / 标题 / URL / 是否当前 / 是否系统页）。**交互快照**（`getInteractive` / `browser/interactive.md`）列出当前页可见的可点、可填控件：编号、角色、标签、当前值、占位、是否在视口内。这是填表和点击的主入口，不要让 Agent 只靠正文纯文本或猜 CSS。
6. **操作**：点击、双击、悬停、聚焦、填写、追加输入、清空、下拉选择、勾选、按键、滚动、等待元素、导航、前进 / 后退 / 刷新。另可按 `tabId` 切换到指定标签（并聚焦它所在窗口），用 `openTab` 新开 http(s) 标签（不要用 `navigate` 覆盖当前页），用 `closeTab` 关闭标签，或把若干标签抽到新窗口 / 搬进已有窗口。**一次填多字段**用 `fillForm`（按编号 / 标签 / name 匹配），避免一格一格猜。**离开页面前**须先 `getUnsavedChanges`：若页面有用户未提交的编辑，不得直接 `navigate` / `reload` / `goBack` / `goForward` / `closeTab`。过程中只是要去别的页拿信息 → 一律 `openTab` 新开，保住当前页；用户明确要求关掉或覆盖当前页 → 先用交互式提问卡（`cursor/ask_question`）说明风险并等确认，确认后才可带 `args.force=true` 执行。未确认的覆盖/关闭会被扩展拒绝并返回未保存摘要。**批处理 / 重复 DOM 操作**可用 `runScript`（`args.code` 为 async 函数体，可选 `world: MAIN|ISOLATED`）在页面里一次跑完，避免逐条 click/fill。
7. **动手前先核对**：自动化开始前先读 `interactive.md` / `snapshot.md`（必要时再截图），对照用户描述。若页面结构、文案、控件与用户说法不符，或目标不明确，先用提问卡确认，禁止瞎点蛮干。能判定为批处理（多行表格、批量勾选、批量导出等）时，摸清选择器后再优先 `runScript`，而不是循环发几十条单步命令。
8. **视觉**：截当前视口，或把指定元素滚入视口后截该元素。图片落到工作区文件，供 Agent 用视觉理解布局、对照文案、规划下一步点击。有交互快照时视觉是补充，不是填表的第一步。
9. 定位元素优先用交互快照里的 `args.index`（从 1 起），其次是关联标签（`args.label` / `args.name` / 可见文本会落到对应控件，而不是落在 `<label>` 或标题上），再次才是 CSS 选择器；可再加 `nth`。点击、填写、悬停前先滚到元素，再把页面上的 **Agent 光标**（参考 page-agent：渐变箭头 + 点按涟漪）滑到目标中心并短暂高亮该控件。光标不拦截页面事件，也不挡我们自己的点击命中。
10. 填写控件时派发完整的 pointer / beforeinput / input / change，并用原生 value setter，以便 React / Vue 等受控输入能收到。原生 `<select>` 按 option 的 value 或可见文本匹配；自定义下拉（combobox / listbox）先点开再点选项。contenteditable 先合成事件，失败再 `execCommand('insertText')`。
11. 导航只允许 `http(s)`。操作完成后刷新当前页快照，并重写交互控件列表（编号可能变）。命令结果里带上新的交互列表，避免 Agent 拿着过期 index 继续点。
12. Host 启动、会话建立时，工作区已写好 `AGENTS.md` 和 `browser/tools.json`，并确保 `outputs/` 存在。Agent 在插件连上的第一时刻就能读到全部页面方法（含截图、标签/窗口、交互快照、`runScript`）以及产物回传 `reportArtifacts`，不必等用户再说明。打开的标签实时写在 `browser/tabs.json`，当前页控件写在 `browser/interactive.md`，Agent 先读这两份再动手，不要猜 tabId 或 CSS。写完会给用户看的文件后必须再调一次 `reportArtifacts`（路径优先 `outputs/...`）。
13. 以下页面不注入、不抓取、不操作、不截图、不跑 `runScript`：`chrome://`、`chrome-extension://`、Chrome Web Store。仍可出现在 `tabs.json` 里并允许 `switchTab`（只是切过去看），但不能对这些页跑页面读/写/截图/脚本。
14. 页面自动化默认执行，不再逐步弹权限（用户装这个扩展就是为了让 Agent 动手）。本地文件写入和 Shell 仍走 ACP 权限条。

### 跨页工作

因为工作区固定，用户可以在 A 页讨论、切到 B 页继续，让当前会话结合两页信息和本机文件做更复杂的事。换一个会话不会丢掉工作区里的页面快照，只是换一条聊天上下文。跨页的默认做法是 `openTab` 新开 http(s)，而不是 `navigate` 覆盖正在看的页（未保存编辑时扩展还会拦住覆盖）。

### 状态持久化

再次打开侧栏时恢复：界面语言、主题偏好、权限模式、会话列表、当前选中会话、每个会话的消息、上次选的模型、选中的 Agent、抽屉状态。`@` 菜单不持久化：标签页只列当前打开的标签，附件只列当前输入栏里的芯片。未发送的附件芯片和消息队列只活在当前进程。聊天不进云端：扩展存储是缓存，**权威副本在本机 `~/.opensider/ui-state.json`**，卸载重装扩展后仍能恢复。用户删光本机 `~/.opensider` 才会真正丢掉侧栏历史。

## 决策记录

| 决策 | 选择 | 原因 |
|---|---|---|
| UI | 自研 ChatPane（lucide） | assistant-ui ExternalStore 的 `useAuiState` 与消息状态不同步，表现为发了没动效、也停不了 |
| 浏览器 | Chromium（Chrome / Edge / Brave 等） | Side Panel + Native Messaging；Firefox / Safari 不做 |
| 与 CLI 的连接 | 预编译 Go 二进制作 Native Host，按需拉起 `agent acp` | 扩展无法 spawn 进程；用户侧不装 Node；每个平台只发一份二进制 |
| 用户安装 | Release `extension.zip` 未打包加载；桥接命令由侧栏给出 | 先装扩展、打开侧栏；缺 Host 时侧栏再给一行壳。README 不写开发入口 |
| Claude ACP 适配器 | `opensider install` 探测到 Claude Code 后 prefix-local 安装 | 官方交互式 `claude` 不带 ACP；缺适配器时自动装进 `~/.opensider/runtime/claude-acp` 并校验；没装 Claude 跳过，没 Node 只提示 |
| 扩展安装包 | 只发 `extension.zip`，开发者模式 Load unpacked | 不上架；不发 CRX。zip 也可给安装壳解压到 `~/.opensider/extension` |
| 附件选文件 | macOS 混选；其它系统侧栏先选文件/文件夹 | Windows / Linux 系统框互斥，不自绘资源管理器 |
| 页面工具 | 内容脚本 + 工作区文件 RPC | 读和写都走同一通道，不必上 MCP、不必再开端口 |
| 填表定位 | 编号交互快照 + label/index + fillForm（参考 page-agent / browser-use） | 正文抽取看不到 placeholder；`innerText` 匹配会打到 label/标题，输入框本身填不进去 |
| Agent 操作光标 | 页面内浮动指针滑到目标再点按（参考 page-agent，不做全屏挡操作遮罩） | 用户要看见 Agent 在点哪里；全屏 mask 会挡住 `elementFromPoint` 和真人操作 |
| 页面自动化权限 | 白名单方法默认执行 | 逐步确认会打断自动化；系统页仍然隔离 |
| 页面截图 | 视口 / 元素 JPEG 写入工作区 | Native Messaging 有 1MB 上限，不能传原图；Agent 用 Read 看图片做视觉规划 |
| 能力发现 | 启动时写 AGENTS.md + tools.json | 会话 cwd 里第一眼就能看见全部方法 |
| 产物回传 | 工作区命令 `reportArtifacts`，Host 拦截后推侧栏 | 扩展看不见本机新文件；不另开 MCP；再次调用覆盖列表；打开位置找不到文件则该项标失效并写入会话 |
| 用户可见产物目录 | 工作区 `outputs/`（AGENTS.md + tools.json 引导；不拦截 Write/Shell） | 产物散落根目录会和协议文件混在一起；产品决定不限制 Agent 本地工具 |
| 工作区 | 全局单一目录 | 跨页连续工作，页面工具不跟会话走 |
| 会话 | 多会话 + 本机持久化 + 右侧抽屉分组 / 置顶 | 用户要新建 / 切换 / 置顶 / 保留历史 |
| 删会话确认 | 非阻塞 popover（16px 安全边距） | 避免误删；`window.confirm` 会卡住侧栏，也不像现有弹出层 |
| Fork | 从某一轮 Agent 回复分出新会话 | ACP `session/fork` 目前不能指定消息；节点分叉用新会话 + 首条上下文 |
| 重新生成 | 同一会话丢掉该轮回复再跑 | 旧 ACP 历史含上次回复，所以换 `session/new` + 前文再 prompt |
| 改历史消息 | 点用户气泡带回输入框再发 | 替换该条、截掉之后，复用重新生成的 `session/new` + 前文 |
| 语言 | 英（默认）/ 中，本机记住 | 只要两种，默认英文 |
| 主题 | 浅色模式 / 深色模式 / 跟随设备，本机记住 | 抽屉设置下拉；token 化颜色保证两套对比度 |
| Agent 模式 | `agent`（完整本地工具） | 用户要求本地工具可用，且过程要在 UI 里看见 |
| 附件 | 文件只传本机路径；元素只传 CSS selector | 扩展拿不到真路径；元素给 Agent 定位，不必上传 DOM |
| 图片预览 | Host 读字节、分片回传、侧栏 `blob:` | 扩展页拦 `file://`；Native Messaging 单帧 1MB，不能整图一次回 |
| 图片预览交互 | `react-zoom-pan-pinch` + 自绘顶栏（lucide） | 只要缩放/平移，不要为 Image 拉 antd；`react-photo-view` 自带 icon，和 lucide-only 冲突 |
| 提及 | contenteditable 芯片 + 当前打开标签 / 当前输入栏附件 | 要和文字混排，并让 Agent 读懂反序列化后的 tab / 路径 / selector；附件历史会和输入栏不同步 |
| 模型 | 各 CLI 的 list 命令 + ACP `configOptions` / `session.models` | 与当前 Agent 账号可选模型对齐，不写死目录；OpenCode 用 `opencode models` |
| Mermaid | `flowchart`/`graph` 用 dagre SVG；其它类型回退代码块 | mermaid 包太重且会污染 DOM、打字时重绘抖动；扩展 CSP 下 HTML 节点也常画不出来 |
| 标签/窗口 | `tabs.json` + `listTabs` / `switchTab` / `openTab` / `closeTab` / `moveTabsToWindow` | Agent 要先看见全部标签才能切换、新开、关闭或抽成独立窗口；走现有命令文件，不另开 MCP |
| 未保存编辑 | `getUnsavedChanges` + 跳转/关闭软拦截 | 有未提交内容时默认拒 `navigate`/`reload`/前进后退/`closeTab`；旁路查信息用 `openTab`；用户确认后才 `force` |
| 批处理脚本 | `runScript`（ISOLATED / MAIN） | 重复 DOM 操作一次跑完；先探索再写脚本；仅 http(s)，有超时与 JSON 结果限制 |
| Cursor 关流字 | 成功轮次吞掉 `WritableIterable is closed` | 这是 Cursor ACP 在内容流完后的可重试拆流，不是侧栏关 stdin；当失败展示会污气泡 |
