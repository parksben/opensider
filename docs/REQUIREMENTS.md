# OpenSider — 需求文档

> 产品名 **OpenSider**。Chrome 侧栏插件：用侧栏自己的聊天面板与本机 Agent CLI（Claude Code、Copilot、OpenCode、Cursor 等 ACP CLI，不要把 Cursor 写在最前）对话，支持多会话、从节点分叉和中英界面，并让 Agent 读取和操作当前浏览器页面。

## 产品目标

用户在 Chromium 内核浏览器（Chrome / Edge / Brave 等）里打开侧栏，就能和本机 Agent CLI 聊天（Claude Code、Copilot、OpenCode、Cursor 等 ACP CLI）。Agent 继续使用本机全部工具（读文件、改文件、跑命令等）。侧栏实时展示工具调用过程，效果对齐在终端 / IDE 里和 Agent 聊天。

所有网页共用**同一个工作区**，因此可以做跨页面的连续工作。聊天本身是**多会话**：用户可以新建、切换，也可以从某一轮对话之后的位置 fork 出新会话。切换标签时，Agent 能知道用户现在在哪个页面，并能抓取页面信息、直接操作页面完成自动化。

### README FAQ

中英文 README 的最底部追加同构 FAQ，排在「工作区与本地数据」之后，先回答两件事：

1. **为什么只支持可通过 CLI 接入的 Agent，不支持带 UI 的桌面 Agent 应用**：OpenSider 的侧栏是 Agent 客户端，不是桌面应用的遥控器。它需要本机桥接程序拉起一个可编程的 Agent 进程，并通过 ACP 完成会话、流式消息、工具调用和权限交互。只有直接提供 ACP，或能通过适配器转换成 ACP 的 CLI 才具备这个接入边界。Claude、Codex 等桌面应用即使与同名 CLI 共用品牌或账号，也没有向 OpenSider 暴露可稳定调用的 ACP 进程接口；模拟点击其 UI 不可靠，也无法完整承载上述语义，因此不支持桌面应用本身。FAQ 给所有产品一条统一迁移路径：到对应产品的官方网站寻找其官方 Agent CLI，按官方文档安装并登录，再重新执行 OpenSider 安装提示词，由安装流程完成探测和可用的 ACP 适配；随后以 Claude Code 与 Codex 为具体示例，分别链接其官方 CLI 文档。不能暗示只装桌面应用即可复用，也不要求用户手工安装适配器；若某产品没有 CLI、ACP 接口或可用适配器，则不能接入。
2. **本机已有 CLI，但侧栏里不能选择时怎么办**：说明“已安装 CLI”不等于“已具备 ACP 接入”；常见原因包括 CLI 不提供 ACP、缺适配器、启动命令不在桥接程序可见的 PATH、或安装状态不完整。给出一段可复制给本地 Agent 的修复提示词，让它读取 OpenSider skill，按 doctor 流程检查、修复并验证。若目标 CLI 没有 ACP 接口或可用适配器，Agent 必须明确说明限制，不得假装已接入。

中文版提示词固定为：

```
帮我排查并修复：本机已经安装的 Agent CLI 没有出现在 OpenSider 侧边栏中。
请先读取 https://raw.githubusercontent.com/parksben/opensider/main/skills/opensider/SKILL.md，按其中的体检与修复流程检查该 CLI 的 ACP 接入方式、启动命令、PATH 和所需适配器，完成可修复项后验证它已出现在侧边栏；如果它没有 ACP 接口或可用适配器，请明确说明。
```

英文版提示词固定为：

```
Help me diagnose and fix an installed Agent CLI that does not appear in the OpenSider side panel.
First read https://raw.githubusercontent.com/parksben/opensider/main/skills/opensider/SKILL.md, then follow its doctor and repair flow to check the CLI's ACP entry point, launch command, PATH, and required adapter. Fix what can be fixed and verify that it appears in the side panel; if it has no ACP interface or usable adapter, say so clearly.
```

## 非目标（v1）

- 不另起用户需要手动启动的本地 HTTP / WebSocket 服务（ACP / 附件仍由 Native Host 按需拉起）
- 用户侧不要求安装 Node / pnpm / Git，也不要求克隆本仓库；安装只保留「把提示词发给自己在用的本机 AI Agent，由它按仓库 skill 执行」这一条路径，不提供 install.sh / install.ps1 之类的手动壳脚本，也不写独立于 skill 的手动安装手册
- 不通过 MCP 暴露页面能力
- 不支持 Firefox / Safari（本机 Core 与浏览器扩展分离，Firefox 后做）
- 不通过页面脚本开放无约束的 Chrome 扩展 API；`runScript` 仅在 http(s) 页内跑、有超时与结果大小限制
- 不把聊天同步到云端
- 不上架 Chrome Web Store。扩展只以 `extension.zip` 分发，用户解压后用开发者模式「加载已解压的扩展程序」（不走商店，不发 CRX）
- 不接入 Claude Cowork（没有 CLI / ACP）

## 用户可见行为

### 安装与连接

1. 用户完成本机要使用的 Agent CLI 登录（Cursor `agent login`、Copilot `copilot login` 等）。不必装 Node。
2. **使用者主路径**（README 只写这一步）：把一段**安装提示词**复制给自己正在使用的本机 AI Agent（Claude Code / Copilot CLI / Cursor / Codex 等），其余交给它按仓库 skill 执行。skill 先跟用户确认常用浏览器、探测本机已装 CLI，再分步完成：下载并校验 `opensider-<os>-<arch>` 二进制 → 放到 `~/.opensider/runtime/`（macOS 清 quarantine）→ 调 `opensider install` 写 Native Messaging 清单 → 问用户把扩展目录放哪里（默认下载目录下的 `OpenSider`，可自定义其它绝对路径），用 `opensider extension-dir <路径>` 记录下来 → 下载 `extension.zip` 解压到该目录（可见目录，方便用户在文件选择器里直接选中；zip 放在同级）→ 打开用户选定浏览器的扩展页并一步步引导「开发者模式 → 加载已解压的扩展程序 → 选中该目录」→ 用 `~/.opensider/host.log` 的新启动行验证已连上。用 AI Agent 是本产品唯一的安装路径，**不提供** install.sh / install.ps1 之类的手动壳，也不把 CRX 当作安装路径。开发加载 `packages/extension/dist` 只写在 DEVELOPMENT.md。`opensider install`（由 skill 调起，不再是用户手敲脚本）会探测本机 **Claude Code 与 Codex**：两家的官方交互式 CLI 都不带 ACP，各有一个官方适配器包（`@agentclientprotocol/claude-agent-acp` / `@agentclientprotocol/codex-acp`）。已装 CLI 本体但缺适配器时，就把它装进 `~/.opensider/runtime/<agent>-acp` 并校验。没装该 CLI 则跳过；没有 Node 18+（npm / pnpm / bun）只提示，不让整次 Host 安装失败。Native Host 由浏览器按需拉起，不是常驻服务；可执行文件在 `~/.opensider/runtime/opensider`。扩展解压目录固定为 `~/.opensider/extension`（skill 下 zip 后解到这里，用户在扩展页加载的就是它；更新就是覆盖同一目录后让用户点「重新加载」）。
3. **桥接未注册**：侧栏打开后若 `connectNative` 报找不到 Host，内容区居中提示：「把下面这段提示词发给你正在使用的 AI Agent，它会先确认你的常用浏览器，再把桥接和扩展装好」（英：Send the prompt below to the local AI Agent you already use. It will confirm your browser, then set up the bridge and the extension.）。下面是可复制的**安装提示词**，按界面语言给中文或英文一份，内容只有「说明用户意图 + 仓库 skill 的入口 URL + 先确认浏览器、分步引导」这三件事。**不再出现**任何 shell 命令、PowerShell 文案、SHA256 或二进制文件名。Service Worker 约每 1–2s 重试连接；Agent 装完桥接后**不必刷新扩展**，提示消失，进入 Agent 列表。Host 已安装但进程崩了只走重连，不再铺安装提示。
4. **连接状态机**（桥接已注册）：侧栏只能走 `missing` → `starting` → `idle` / `ready`，或落到可见的 `error`。**禁止永远停在 starting**：Host 必须立刻应答 `hello` / `status`（先报 starting，CLI 探测在后台做）；探测有总时限，不能卡住 Native Messaging 读循环。若约 10s 还停在 starting，Service Worker 改报 `error`，文案指向 `~/.opensider/host.log`（扩展 ID / Host 名仍附上）。**「没有找到可用的 ACP CLI」只在探测已经完成且名单为空时出现**；Host 还在 starting、看门狗超时、或还没收到 `agents` 时，只说明连接/启动失败并给重试，不能假装本机没装 CLI。已收到非空 `agents` 就画名单，即使随后有一条 starting 超时。点顶栏「重连 / Connection」必须真正拆掉旧 Native 端口再连，不能因为上一次探测没结束就空转。从 Node Host / 旧目录迁过来的 `~/.opensider`（`PickFiles.app`、旧 `session.json`、`runtime/packages` 等）可能不兼容，skill 的安装与修复流程要能识别并处理这类残留（先备份、再重建 runtime / workspace）；开发机用 `pnpm install-host` 重建。
5. **首次选择 Agent**（桥接已就绪、本机还没有完成过引导）：Host 探测本机已安装、且能用 ACP 握手的 CLI（不限于内置名单：已知启动方式 + 本机 PATH + nvm / npm-global / bun / `~/.opencode/bin` 等版本管理目录 + ACP Registry）。Chrome 拉起 Native Host 时 PATH 很瘦，不能只搜 `/usr/bin`，否则会漏掉装在 nvm 里的 Copilot 等 CLI。探测只用来列名单：二进制在即可列入，短超时握手失败也保留；真正连接再走完整握手。**Claude Code 的交互式 `claude`、Codex 的 `codex` 本身都不是 ACP**，探测的是适配器 `claude-agent-acp` / `codex-acp`；只装了 CLI 本体不会出现在名单里。`opensider install` 若发现某家 CLI 而适配器缺失，会自动装到 `~/.opensider/runtime/<agent>-acp` 并校验，装好后探测即可列入；没有 Node 只提示，不失败。重新跑一次 OpenSider 安装，或先用该 CLI 登录，即可补上。引导区相对标题栏下方的内容区垂直居中。不画 CLI logo（本机没有产品标）。提示「点击 Agent 以开始连接」，下面是一排较大的纯文本按钮，点哪家就连哪家，不要再加确认钮；按钮有和别处一样的涟漪。探测尚未完成时转圈「正在查找本机 Agent CLI」，不要先甩一张空名单。连接若超过约 300ms，展示分步进度（解析 / 拉起 / 握手 / 鉴权 / 会话 / 模型）。进度条文案同一行最右侧是纯文本「取消 / Cancel」（不要 emoji）。进行中或卡住都可以取消**这一次**连接，但已经 `ready` 的连接不能用这个按钮拆掉。取消后回到**取消前**的状态：若之前已连上另一家 Agent，保持那一家（旧进程尽量不停，必要时再握手）；若之前没有已连接的 Agent，回到名单 / 未连接，不要停在新一家的半连接或失败态。成功后进入聊天。之后顶栏左上角是 Agent 下拉（纯文本 + 名），可换家；下拉必须浮在消息之上，点得到。换 Agent 时同一套进度条和取消钮出现在顶栏进度区（状态文案「4/6 · Signing in」右侧）。模型列表跟当前 Agent 的 `configOptions` / `session.models` / 其 list 命令走（Cursor：`agent models`；OpenCode：`opencode models` 的 `provider/model` 行，连上后若会话里还没有名单再拉一次）。只展示 Host 真正拿到的条目，不编一份假目录。Copilot 若 CAPI 名单为空，用它 CLI 内置的公开模型表兜底。**只有确认名单为空才藏下拉**，不能因为 `ready` 比模型列表先到就留一个空槽。换 Agent **不丢**本机会话：历史仍是侧栏自己的消息；老会话用新 Agent 继续聊时，把本地前文交给新的 ACP 会话。Gemini 若报 `EACCES` 写 `~/.gemini`，是本机目录属主不对（常见于曾经 `sudo` 装过），不是侧栏协议实现错了，错误文案要写明 `sudo chown -R "$(whoami)" ~/.gemini`。macOS 从 Chrome Native Host 拉起 CLI 时，Host 必须把该进程的 `TMPDIR` 钉到 `~/.opensider/runtime/natives/<agent>/`（稳定路径，不要每次落到 `/var/folders/…` 随机名），并对解出的小型 Mach-O（`.node` / `.dylib`，不含 CLI 本体）清 quarantine、做 adhoc 签名，避免「系统无法验证 / 未识别该文件」连弹十几下。不要改、不要重签用户的 CLI 大二进制（Apple Silicon 会拒改过的 arm64）。若仍弹出一次，点「完成」并在隐私与安全性允许，不要「移到废纸篓」。**OpenCode 1.18+ 的会话 mode 是 `build` / `plan`（走 `configOptions`，不带 `modes`），没有 `bypassPermissions` / `auto`**：这类工作流模式由侧栏的「Agent 模式」下拉显式切换（见《聊天》第 18 条），Host 只在会话真正广告过的集合内发值，盲发未知 mode 会让会话设权限失败。OpenCode 发消息若报 API key 无效，侧栏要写成「先在终端跑 `opencode auth login`」，不要只丢一段 JSON-RPC。**Gemini** / **Claude ACP** 的 npm addon、**Copilot** npm 版仍可能带未公证 `.node`，同一套 TMPDIR + 签名兜住；官方 cask `copilot-cli` 已公证。
6. 点击工具栏图标打开 Side Panel。顶栏从左到右：左侧是 **Agent 下拉**（已连接时），未连接时才是连接状态（启动中 / 离线 / 出错）；**宽度足够时会话标题绝对居中**，单行省略，只展示、不可在顶栏改名；**最右侧只留一个**抽屉按钮：关闭时 Lucide `ChevronsLeft`（向左双箭头，打开抽屉），展开后 Lucide `ChevronsRight`（向右双箭头，收起）。tooltip 为「展开 / Expand」与「收起 / Collapse」，不要再写历史会话 / Past chats。顶栏不再放开关灯、语言切换，「新会话」也不在顶栏。宽栏时顶栏只有三块：左 Agent 下拉（或未连接状态）、中会话标题、右抽屉钮。**会话主体**（顶栏+消息+输入，不含右侧抽屉）宽度 **小于 348px** 时进入窄布局：隐藏 Agent 下拉，标题改为居左；抽屉钮保留。窄布局由主体宽度决定，无论是拖 Chrome 侧栏还是打开/拖宽会话抽屉把主体挤窄，都要立刻切换。顶栏不再放当前页 favicon。offline 时状态旁有「重连 / Connection」（旋转箭头 icon 已表示重试，英文不再写 Retry）。不再单独铺一条当前页 banner。不放插件名和 slogan。未连接时说明原因。重连必须真正重连 Native Host，不能因为端口已断开就静默失败。两套主题的正文、次要文案与背景对比度都要够读，不能在某一主题下糊成一团。全栏默认字重 **400**，标题 / 强调 / Markdown 加粗一律 **500**，不用更重的 600/700。
7. 顶栏标题只展示、不可点击改名；重命名只在右侧会话列表卡片上进行。标题不设固定字数或固定像素上限；被右侧操作区挤住才单行省略，hover 用原生 `title` 看全文。**宽栏居中**时左右各留 **32px** 安全距（避开 Agent 与抽屉钮），「新会话」/「New Chat」也要看得见，不能因为居中槽位塌成 0 宽而消失。**窄栏居左**时标题从状态条右侧（没有则顶栏左缘）起排。**未命名会话不写默认标题进数据**（`title` 保持空）；顶栏和会话列表只在展示时用「新会话」/「New Chat」。标题为空，或仍是「新会话」/「New Chat」/「New chat」时，用户发出一条消息后用该条正文首行（没有正文则用附件名）作为标题，不再按字数截断。点最右侧侧栏按钮打开**右侧抽屉**（不是居中模态、没有遮罩）：抽屉推出时把整栏主体（顶栏、消息、输入框）往左挤。抽屉左缘可拖，改变宽度时同样挤压主体。展开/收起与宽度写入本机。抽屉顶部两个 tab：「会话 / Sessions」（左 Lucide `MessageSquare`）和「设置 / Settings」（左 Lucide `Settings`），只这两个，不要第三栏。**会话** tab 自上而下：全宽筛选（按标题不区分大小写；中文占位「输入关键字以筛选会话...」，英「Filter sessions...」，输入框上下内边距各比原先多 8px）→ 全宽「新会话」按钮（Lucide `Plus` + 文案）→ 按时间聚合的会话列表。**设置** tab 放主题和语言，各是一行带前缀的下拉：左边灰色 Prefix（中「主题」「语言」，英 Theme / Language；深色用 `--muted`，浅色同样走 `--muted`，保证比正文浅一档），右边是当前选项，点开下拉选。主题三项文案：浅色模式 / 深色模式 / 跟随设备（英 Light / Dark / Device），下拉项左侧保留 `Sun` / `Moon` / `Monitor`；语言两项文案不随界面语言变：中文项一律「简体中文」，英文项一律 English。不要再做成顶栏 icon 循环切换。分组从左标题（紧贴右侧 Lucide 展开/收起箭头：展开 `ChevronDown`、收起 `ChevronRight`）、右侧该组条数；整行可点，切换展开收起；组头上下各比原先多 4px 内边距。若有置顶则最顶是「置顶 / Pinned」；其余未置顶按本地日历分成「今天 / Today」「最近 7 天 / Last 7 days」「更早 / Older」；空组不出现。组内按 `updatedAt` 倒序。卡片上下内边距各比原先多 8px。卡片左侧空闲是小圆点，进行中换成六点盲文字符循环 spin，不再在标题旁转圈。标题与置顶 / 重命名 / 删除三个按钮同一行垂直居中；按钮仅鼠标悬停该卡片时出现，移出后从布局里拿掉，标题占满剩余宽度、单行省略。点会话只切换、不关抽屉；Esc（不在输入框里时）或再点顶栏按钮收起。上下键循环高亮并滚入视口，回车切换。语言和主题只在抽屉「设置」tab 里用下拉切换，不再占用顶栏。
8. 连接成功后，Host 按当前选中的 Agent Profile 拉起对应 ACP 进程（Cursor 仍是 `agent acp`，其它见 TECH_DESIGN），复用该 CLI 已有登录。登录失效（例如 OpenCode `Authentication Fails` / api key invalid）必须在侧栏可见，并带上该家的登录命令。关掉再打开侧栏时，应回放最近一次连接状态，而不是一直停在离线。侧栏与 Service Worker 之间的端口断开时，不得抛未捕获异常（Chrome 扩展页里那种 `disconnected port object`），并应自动重连；不要停在「Lost connection to the extension service worker」就不再试。
9. 用户发送后，侧栏立刻出现用户气泡，输入框描边进入进行中动效。进行中发送钮仍可点（入队），旁边保留停止钮。不再另起一行「Agent is working」转圈。离线时发送会留下可见错误，而不是没有任何反馈。

### 安装、更新与卸载（skill 驱动）

安装 / 更新 / 卸载不再由仓库里的壳脚本承担，而是「**一段提示词 + 仓库里的 skill**」：用户把提示词发给自己在用的本机 AI Agent，Agent 按 skill 逐步执行、每步验证、失败给可执行的修复动作。仓库仍发预编译二进制（用户侧不装 Go），但不再发 `install.sh` / `install.ps1`。

1. **提示词只有两行：意图 + 入口 URL**：让 Agent 读取 `https://raw.githubusercontent.com/parksben/opensider/main/skills/opensider/SKILL.md` 并「按其安装 / 更新 / 卸载流程执行」。**不要往提示词里塞 skill 已有的约束**（确认浏览器、选扩展目录、分步引导、每步验证全由 skill 负责）——两处都写一遍只会互相干扰，改 skill 时也容易漏改。README「安装使用」与侧栏弹窗给的是同一段（中英各一份，逐字一致）。
2. **skill 自举**：`SKILL.md` 先解析 GitHub `releases/latest` 指向的 tag，再用**该 tag** 的 raw 地址拉取其余 skill 文件与 release 资产，保证 skill 与二进制同版本；解析不到 tag（离线 / 被墙）时退回 `main`，并明确告诉用户「版本可能不匹配，建议联网重跑」。
3. **多文件结构**：入口 `SKILL.md`（能力清单、决策树、阶段顺序、验证门）+ `install.md` / `update.md` / `uninstall.md` / `doctor.md` + `references/`（平台与浏览器路径矩阵、下载方式、CLI 与 ACP 适配器表、验证判据、故障排查）。文件在仓库里，agent 用 curl **并发**拉取，不要求用户装 Git、克隆仓库或再装 aria2 / gh。GitHub 官方 CDN 支持的并发方式是：多个独立文件并行 GET；release 大文件先解析 `releases/download` 的 302，再对 `release-assets.githubusercontent.com` / `objects.githubusercontent.com` 做并发 Range GET（`Accept-Ranges: bytes` → `206`），但这套只在**直连链路**上用。**下载链路要先判网络环境，还要破缓存**：花两三秒判定一次（地区提示：`https://www.gstatic.com/generate_204` 的连通性 / 延迟对比百度；决定性证据：对 release 资产实测首字节 `%{time_starttransfer}` 与 512KB 分片的实测速度（`size_download / time_total` 自己算）），结论只有 `direct` 或 `mirror` 两种并**整轮沿用**（某条链路连挂两个文件才允许换一次），判定结果要告诉用户。国内判定或直连实测不达标时，按顺序试国内代理：`https://gh-proxy.com/<原始 GitHub URL>`（首选，实测支持 Range `206`，但它是 Cloudflare 缓存）、`https://ghproxy.net/<原始 GitHub URL>`（次选，**不要**拿它做单文件 Range 切片，实测会截断），raw 小文件还可走 `https://gcore.jsdelivr.net/gh/parksben/opensider@<tag>/…`（只钉 tag，不要用它取 `main` 上的兜底文件，分支路径缓存很黏）。镜像只当**加速通道**，不是可信来源（会挂、会串缓存、可能返回别的页面）：顺序尝试、全失败退回直连、并**一律 sha256 校验**。会变的两处必须破缓存——`releases/latest` 与 `main` 上的文件：`?t=<unix 秒>` 只加在**镜像 / 代理 URL** 末尾（别动 GitHub 的签名链路）+ `-H 'Cache-Control: no-cache'`（实测能把 gh-proxy 从 `cf-cache-status: HIT` 打成 `MISS`）。`SHA256SUMS` 与二进制要走**不同链路**（直连拿不到就换另一个镜像），别让同一个镜像的缓存自己证明自己；校验不过时先换链路 + 破缓存重取一次，仍不匹配才停下报错。npm 依赖（ACP 适配器）按同一套判定：国内时在 `opensider install` 前加环境变量 `npm_config_registry=https://registry.npmmirror.com`（Go 侧 `cmd.Env = os.Environ()` 会透传给子进程 npm）。**进度要可见**：每个操作先把阶段列成 todo list 给用户看（有 todo 工具就用工具，否则用对话里的清单），每过一个验证门就更新一项——用户要能一眼看出装到哪了。
4. **必须先问浏览器**：安装前跟用户确认「平时用哪个浏览器」。优先列出本机检测到的 Chromium 浏览器（Chrome / Edge / Brave / Chromium / Vivaldi / Arc 等）让用户挑；**只有一个也照样问**（「本机只检测到 Chrome，就装它吗？」），用户点头才算确认——不能拿「本机只有它」当默认答案自己往下走；一个都没检测到就引导先装浏览器再回来。Native Messaging 清单仍然写进**所有**检测到的浏览器与其各 Profile，但「加载已解压扩展」的引导只针对用户选定的那一个。
5. **扩展目录要问用户，并记住答案**：安装时把「扩展目录放哪儿」当成**必须等用户回答**的一步：候选摆出来（建议 `~/OpenSider`；也可以 `~/Downloads/OpenSider`，但要说明清理下载会把它删掉、扩展会因此失效；其它绝对路径都接受；**不接受**放进 `~/.opensider`，点目录在文件选择器里不可见），**用户没回答前不得建目录、不得下载、不得落盘路径**（顺序硬性：先问 → 等回答 → 记录 → 再下载解压），也不得把 Agent 自己的建议当默认默默执行；用户回避或没回答就再问一次，不要替他选。选定的路径要落盘（`~/.opensider/extension-path`，通过 `opensider extension-dir <路径>` 写入，读取用不带参数的同一个命令），后续更新 / 体检 / 卸载都从它读，不得各处自己猜。skill 下载 `extension.zip` 解压到该目录（重复安装就是覆盖），zip 放同级供用户复用。用命令打开选定浏览器的 `chrome://extensions`（macOS `open -a "<浏览器>" "chrome://extensions"`；Linux / Windows 用对应浏览器的可执行文件带该 URL），然后逐步引导用户：打开开发者模式 → 点「加载已解压的扩展程序」→ 选中该目录 →（可选）固定到工具栏。这一步**必须有用户手动操作**，skill 不得假装自动完成，也不得因为用户还没点就说安装成功。这个目录要长期留在原处（Chrome 每次启动都从这里读扩展），skill 要告诉用户别移动或删除它。
6. **验证判据**：以 `~/.opensider/host.log` 出现新的 Host 启动行 + 用户确认侧栏已列出本机 Agent 为准。分不清「本机没装 CLI」「桥接没注册」「扩展没加载」时不许下结论，按 `references/troubleshooting.md` 分流。
7. **更新是半自动的**：skill 的 update 流程对比已装版本（扩展 `manifest.json` 的 `version`、`opensider version`）与最新 release，覆盖二进制与扩展目录，再引导用户在扩展页点「重新加载」，最后同样以 host.log 验证。扩展侧只做检测与提示，不做后台静默自我更新（见第 11 条）。
8. **卸载**：先请用户关掉侧栏（桥接进程是浏览器按需拉起的，只要侧栏还连着它就会继续把 `~/.opensider/workspace` 写回来，让人以为卸载没生效）；然后移除所有浏览器 / Profile 下的 `com.opensider.host.json`（含历史 `com.cursor.sidebar.host.json`）与 Windows 注册表项、删 `~/.opensider/runtime`，并**明确询问用户**是否清空 `~/.opensider`（工作区、会话历史、产物、日志、界面状态一并说明后果：清空即丢历史与产物）。卸载命令要检测仍在运行的桥接并给出 pid 与「先关侧栏再跑一次」的提示；skill 在清理后要复查 `~/.opensider` 是否真的没了（又出现就是侧栏还开着）。扩展本体由用户按引导在扩展页移除。
9. **体检（doctor）**：只读检查 + 修复常见问题——二进制缺失 / 不可执行、macOS quarantine、清单未覆盖某些浏览器、Node 与 ACP 适配器缺失、workspace 不完整、host.log 长期没有启动行。doctor 不动用户数据。
10. **不提供纯手动逃生通道**：不写「不用 AI Agent 也能装」的脚本或手册；没有可执行命令能力的 AI（例如纯网页版对话）不适用于安装，skill 要明确指出并建议用户换一个有本机 shell 能力的 Agent CLI。
11. **版本检查（半自动）**：Host 在 `hello` 里带自身版本；最新版本由 Host 查 `releases/latest`（结果缓存 **1 小时**：一小时最多问一次，既安静又不会出现「刚发完新版，一天内都还说最新是旧的」；失败静默降级，不打扰用户）。侧栏设置 tab 展示「扩展版本 / 桥接版本 / 最新版本」三行，**三行同口径：一律不带 tag 的 `v` 前缀**（`v` 只在 release 标识里出现），下面两个**文案居中**的按钮：「检查更新」（点后强制重查一次，**必须有明确反馈**：先显示「检查中…」→ 真发现有新版本就直接弹出更新提示词模态窗；已是最新则按钮短暂显示「暂无新版本」；等不到 Host 回话（离线 / 桥接没起来）显示「检查失败」。后两种亮 1.5s 后回到「检查更新」，不允许默默变回原样）与「一键卸载」（点开模态窗，里面有卸载提示词与「复制提示词」，形状与更新模态窗一致——都不在本机真做动作，而是把提示词交给用户的 AI Agent）。模态窗的观感、按钮与复制反馈要与侧栏其余部分同源（描边按钮 + 涟漪，复制后显示「已复制」），不要另创一套强调色的主按钮。弹窗正文只有一句话——「复制并发送以下提示词到本地 Agent，根据 Agent 的提示完成更新 / 卸载」，不要在弹窗里替 Agent 复述它接下来会做什么（那些细节写在提示词与 skill 里）。
    发现扩展或桥接落后于最新版时：**顶栏最右侧抽屉钮的左边多出一个更新图标按钮**（lucide `CircleArrowUp`，主题强调色 + 右上角小圆点；没有新版本时完全不出现，窄栏布局下也保留）。点它弹出**模态窗**（居中卡片、遮罩带模糊，Esc / 点遮罩 / 右上角叉关闭）：窗内列出三个版本 + 一句「把它发给你的 AI Agent」的说明 + 可滚动的更新提示词 + 「复制更新提示词」主按钮（复制成功后原地变「已复制」）。更新动作仍由 Agent 按 skill 执行，扩展不做后台静默自我更新。README 中英各带「版本更新」「卸载」两节，内嵌的提示词与界面上复制到的一致；三段提示词（安装 / 更新 / 卸载）都在 `platform.ts` 里定义，不要各处手写。
12. **安装 / 更新成功后代点 Star（能点就直接点，且绝不允许取消已有的 Star）**：流程真的走完（安装完成或更新已验证）之后，skill 用 GitHub API 先**查**当前用户是否已给仓库点过 Star（`GET /user/starred/parksben/opensider`：`204` 已点 / `404` 未点），已点就什么都不做（最多一句谢谢）；未点则**直接** `PUT /user/starred/parksben/opensider`（幂等，重复点无害），**不问用户**——机器上已经有该用户的 GitHub 凭据（`gh` 已登录，或环境里就是他自己的 `GITHUB_TOKEN`）就说明这个层级的账号操作是被默许的，事后在收尾报告里一句话说明即可。**任何情况下都不得调用 `DELETE /user/starred/…`**：把用户点过的 Star 取消掉是这套流程里唯一不可挽回的错误，看起来就是 bug。没有 `gh` / 未登录 / `403`（token 没有星标写权限，classic 需要 `repo` 或 `public_repo`）/ `401` 时不许重试、不许让用户重新登录，改为一行引导 + 帮他打开仓库页（`open` / `xdg-open` / `start`），并说明不点 Star 丝毫不影响使用。文案跟用户当前语言（拿不准时读 `~/.opensider/ui-state.json` 的 `locale`）；只说一次，不做后续追问，也不把 Star 当成任何步骤的前置条件；安装/更新失败时一句都不提。
13. **本机没有受支持的 CLI 时不中止安装**：桥接与扩展照装（装好就等 CLI，装上 CLI 后下一次连接就列出来，不用重装），但 skill 必须明确告知用户：OpenSider 不内置 Agent、要驱动一个本机已装的；给出具体该装哪一个（附安装 / 登录命令；如果用户此刻正在用 Claude Code / Codex，那就是装对应的 ACP 适配器，另需 Node 18+）；并说明侧栏此刻会显示「没找到 CLI」是预期现象。skill 不得把「没装 CLI」当成安装失败，也不得反过来假装装好了。

### 聊天

1. 侧栏是唯一的对话入口。消息列表、输入框、进行中状态由侧栏自己渲染，不依赖 assistant-ui 的 runtime 选择器。空会话在消息区垂直居中放产品 logo（与扩展图标同一套，约 120px，透明度 30%，并用 CSS 把饱和度降到约 20%）和一行淡灰提示：发送消息，开始与 Agent 就网页内容聊天（英：Send a message to start chatting with Agent about this page）。Logo 和这行提示都禁止鼠标划词选中。提示两侧各留约 200px，宽度够就不要换行；侧栏太窄再折行。
2. 用户气泡宽度随内容收缩，最大不超过消息列表区域总宽的 80%，靠右。用户发送消息后，该气泡固定在这一轮的位置，本机 Agent 的正文和工具调用只追加在它后面，不得写进上一轮回复里把这条气泡往下挤。输入框占位固定提示「回车发送 · Shift+回车换行 · 输入@引用标签页或附件 · 输入/指定 skill」（英：Enter to send · Shift+Enter for a new line · Type @ to reference tabs or attachments · Type / to use a skill），不随连接状态变化。未进行中时输入框获得焦点，四条边框都轻微提亮（深色略亮、浅色略深，对比不要强），过渡约 160ms，不要拖到接近半秒。占位只是空态提示，不是可编辑内容：删光正文和芯片后，光标停在内容区最前面，不能停在占位文案后面。文本输入区是可混排芯片的富文本（不是纯 textarea）：默认高度为 2 行正文；内容变多时跟着长高，满 10 行后出现滚动，并始终把光标所在行滚进可视区。当前会话进行中时，输入框描边换成 Chrome Logo 四色圆锥渐变（红 `#EA4335`、黄 `#FBBC05`、绿 `#34A853`、蓝 `#4285F4`），先过渡铺满 360°，再以 4 秒一圈持续旋转；结束后整圈淡出，回到原来的细线，不要把描边收起来。**会话主体宽度 ≤ 448px** 时，权限与模式两个下拉都收成纯图标（**不隐藏**，tooltip 完整给出「名称 — 含义」；这个 448px 阈值与下面 348px 的整套 compact 布局分开：两个下拉收得早，其余元素该怎样还怎样）；回形针 / 拾取 / `@` / `/` 四个功能钮此时已经收进 `+` 按钮（600px 阈值更高、先于这一档生效，见下），**不隐藏也不失效**，右侧仍留模型选择与发送 / 停止。输入区和工具栏分两行：第二行左侧从左到右是回形针（添加附件）、拾取元素、`@`（提及）、`/`（指定 skill，见第 21 条）、**Agent 模式下拉**（内容由该 Agent 自己广告决定，见第 18 条；没有可切换的模式时整个控件不出现）、权限模式下拉（四档：默认权限 / 允许文件修改 / 允许工具调用 / 允许一切操作；每项模式名 + 灰色小字：用户确认后方可调用工具 / 允许工作区内文件修改，执行命令、联网操作仍需确认 / 直接执行工具调用，问题和计划仍需确认 / 工具、问题、计划无需确认。英：Ask every time / Allow workspace edits / Auto-run tools / Allow all；灰色小字 Confirm each tool / Workspace file edits skip confirmation; commands and network still ask / Tools skip confirmation; questions and plans still need a click / Don't ask about tools, questions, or plans）。回形针 / 拾取 / `@` / `/` 四个图标钮（或收起后的 `+` 按钮）与这两个下拉**紧挨成一组、整体居左**：两个下拉都**不参与撑开**（`flex-grow: 0`，按内容宽度收缩、过长才截断），多余空间留在这一组与右侧的模型选择 / 发送之间，不得把两个下拉拉宽了往中间推。**两个下拉与图标钮共用同一套间距节奏**：内边距一律对称 8px（不要内侧收窄，两个钮的左右内边距必须一致），两个下拉之间的间距跟图标钮到第一个下拉的间距一样（4px，不要把两个钮贴死）。模式钮按内容宽度收缩、不加最小宽度（否则会多出一段「看不见的空白」，看起来像两个钮之间还有间距）。右侧是模型选择、**思考档位**（仅当引擎广告了 `thought_level`，见第 19 条）和发送钮。**宽度 ≤ 396px 时，模型下拉的最大宽度收到 80px**（思考档位钮按内容自适应，只在真的挤不下时才省略）（常值是 9.5rem；这一行此时已经挤了五个控件，模型名是唯一能让位的。试过收到 1/3（约 51px），读起来太窄；与 448px 的「两个下拉收成图标」分开，各自独立生效）。权限与模式是**两个独立概念**：前者是我们的拦卡档位，后者是 CLI 自己的工作流模式，不得合成一个控件。工具栏始终单行：宽度不够时（例如进行中多出停止钮），权限与模式两个触发钮的文案各自先单行省略（不换行）；权限钮有最小宽度（约 5rem，够放下图标和省略号），模式钮按内容收缩（不加最小宽度），触达该最小宽度之后才允许挤压右侧模型选择，其触发钮文案同样单行省略。窄到只留图标时（≤ 448px，见上），两个触发钮都只画图标，宽度按图标钮算，tooltip 给出「名称 — 含义」。省略只作用在触发钮文字上，**不得**把权限/模型下拉的弹出层裁掉；点触发钮必须能弹出完整菜单（与模型下拉同一套可见行为）。下拉菜单项仍显示全文。发送 / 停止图标钮不参与挤压。回形针、拾取、`@` 和 `/` 四个图标按钮之间间距为 0，不留缝。**会话主体宽度 ≥ 600px 时这四个功能钮平铺**；**< 600px 时收成一个加号按钮**（Lucide `Plus`，占原第一个钮的位置、不额外占宽）：hover 或点击在按钮上方弹出这四个功能——非 Windows 四项（添加附件、拾取元素、`@`、`/`），**Windows / Linux 五项**（选择多个文件、选择多个文件夹、拾取元素、`@`、`/`，即把第 3 条的附件下拉并进这一层，不必再点回形针）。**加号钮不带 tooltip**：它的弹层就在按钮正上方，tooltip 一定会盖住菜单内容，而弹层里的文字已经说明了一切（按钮仍保留无障碍名称）。**图标钮自己的菜单打开时不显示 tooltip**（`@` / `/` / Windows 下的回形针同理），免得同样的遮挡发生。弹层复用附件下拉的定位与样式；点层里的 `@` / `/` 时仍以加号按钮为锚点唤起各自菜单。收起只改鼠标入口，在输入框里直接敲 `@` / `/` 唤起的路径不受影响。发送钮用 Lucide 小飞机纯图标；进行中停止钮与发送钮并存（发送入队）。所有纯图标按钮都有 tooltip，须完整落在侧栏视口内并与边缘留出安全距离，不得被裁切。次要按钮（描边 / 透明底：新建会话、会话卡片操作、Agent 回复下的 fork / 重新生成等）hover 为半透明覆盖（深色偏白、浅色偏黑），点击有 CSS 涟漪；**主按钮（强调色实心：权限条「接受计划」「继续」、删除确认的确认钮、复制提示词、发送等）hover 必须是自身强调色的加深 / 提亮，不得套中性半透明灰（会被读成禁用态），点击同样有涟漪动效**。历史会话在右侧抽屉里打开，不遮罩。
3. 回形针要本机绝对路径，不能用页面 `<input type=file>`。系统种类用浏览器 UA（优先 `userAgentData.platform === "macOS"`）。macOS：直接开一个可同时多选文件和文件夹的系统框。Windows / Linux 的系统框不能混选：点击回形针后在按钮上方立刻弹出下拉（不是全栏模态），两项为「选择多个文件 / 选择多个文件夹」，再开对应系统多选框；两种都要则再点回形针。未连上 Host 时回形针留下可见错误，不能静默没反应。Host 按 UI 传来的 mode 去 `opensider pick`（独立进程才能把面板拉到前台）。输入框支持直接粘贴截图（或剪贴板里的图片）：粘贴后进入同一套附件芯片，随这条消息一起发出；同一张图只生成一个芯片，不要因为剪贴板同时带 files / items 就写两份。未连上时留下可见错误，不能只把图片糊进文本框。拾取按钮用光标 icon：点后**整栏**立刻被带背景模糊的遮罩盖住，提示叠在遮罩上；点遮罩不取消。网页进入拾取态（十字光标、悬停高亮），再点一下即拾取。遮罩和提示只在拾取完成或按 Esc 后消失。已打开的 http(s) 页即使还没注入过内容脚本，点拾取也会补上，不必先刷新。YouTube / youtu.be 视频页（含从首页点进 `/watch` 的 SPA 跳转）同样要能进入拾取：至少能点到标题、评论、相关视频等页面骨架；播放器若在 iframe 里，点不到内部控件也可以，但不能把整页当成系统页拒掉，也不能点了没反应。补注入失败必须留下可见错误。选中后在文本框上方以芯片展示。文件芯片和拾取元素芯片同一套尺寸：最大宽度约 200px，超出省略，悬停用 title 看全文；图片 / 普通文件 / 文件夹 / 拾取元素用不同 lucide 图标；芯片右侧可删。从附件栏删掉某项后，正文里对应的 `@` 附件芯片也要拿掉，`@` 菜单不能再提到它。输入栏附件和用户气泡里的图片芯片可点：全栏弹出模态预览，遮罩约 2px 背景模糊，颜色跟侧栏 `--overlay` / `--panel` 走，不要另起白底灯箱。图相对视口绝对居中，按自身像素显示；太宽则等比缩小，左右各留视口宽度的 10%。预览要能放大、缩小、拖拽平移和复位（滚轮 / 捏合 / 拖拽 + 顶栏按钮）。顶栏用 lucide：`ZoomIn` / `ZoomOut` / `RotateCcw`（复位）/ `X`（关闭），tooltip 中英都要。点遮罩、点关闭或 Esc 退出；点图片本身不关，否则和拖拽打架。进行中仍可预览，不要因为气泡不能改历史就把图片点不了。Chrome 扩展页即使 CSP 写了 `file:` 也显示不了 `file://` 图，所以预览必须由 Host 读本机文件，再经 Native Messaging 分片回侧栏（单帧不超过 1MB），侧栏拼成 `blob:` 给 `<img>`。只预览用户已经挂上的图片附件路径，不接受任意 URL。加载中在正中转圈，不要静默失败；转完再露图。失败则居中显示「无法加载这张图片」（英 Couldn't load this image），句末不加句号。文件附件发给 Agent 的是本机绝对路径，不上传内容。元素附件带全局唯一 CSS Selector（等同 DevTools「复制 selector」），并说明这是用户在当前页拾取的节点，供 Agent 查看或操作。没有正文、只有附件时也可以发送。附件不写入本机历史。
4. `@` 按钮在拾取按钮右侧。点击后把光标移到输入区最前面并插入一个 `@`，同时打开提及菜单。菜单是跟着**当前光标**的弹出层，优先出现在光标上方，不得挡住正在输入的那一行；整层与侧栏视口四边保持 16px 安全距离，空间不够则缩短列表高度并内部滚动，不要贴边或画出界面。两个 tab：**标签页**（当前浏览器普通窗口里正在打开的标签，左 favicon、右标题；不缓存已关闭的历史标签）和 **附件**（只列当前输入栏里还未发送的附件芯片，左 kind 图标、右名称，样式对齐附件栏但不带关闭钮；不读、不写本机附件历史）。**菜单打开期间**，光标前 `@` 之后继续输入的内容即搜索词（不另起筛选框）；删光 `@` 或把光标移出该 `@` 触发区则关闭菜单。搜索不区分大小写：标签页匹配标题与 URL，附件匹配名称与路径；标题 / 名称优先于 URL / 路径排序；匹配字符在标题 / 名称上直接换成主题强调色（不要选中块底色）；无匹配项过滤掉，关键词越长列表越短。标签页按当前打开的 `tabId` 列出，同一 URL 开了多个就显示多条；关掉的标签立刻从列表消失。键盘：Tab / 左右键切菜单 tab；上下键在当前**筛选结果**里循环高亮，列表跟着滚到高亮项，到头再按则绕回另一端；回车只把高亮项插成芯片，**不得发送消息**；Esc 关闭。鼠标：可点 tab 和选项，同样只插入、不发送；点击不得让输入区失焦（mousedown 先记下选区，插入前再恢复）。选中项以芯片插入正文，替换光标前的 `@` 及紧跟的搜索词，和文字流式混排：芯片 DOM 两侧各补一个空格；插入点前面已经是空格则不再补左边，后面已经是空格则不再补右边。芯片高度必须等于所在行正文的行高（和划词选中时那块底色一样高），不得跟着芯片里的小字塌下去；内容相对这个行高容器垂直居中。容器右侧 padding 12px、左侧 8px。最大宽 200px、超出省略，悬停用 title 看全文。点击芯片不得把光标放进芯片内部，应落到该芯片后方；芯片容器内禁止划词选中。发出去的用户气泡用同一套芯片混排渲染。发给 Agent 的正文要把芯片反序列化成它能读懂的结构化说明（提及的标签页给 title / URL / tabId，提及的附件给路径或 selector），不能只剩一个看不懂的 `@`。
5. 未连上时不展示模型下拉。连上后只展示 Host 从该 Agent 的 list 命令（Cursor `agent models`、OpenCode `opencode models`）和 ACP `configOptions` / `session.models` 拉到的列表，不自己再塞选项。OpenCode 的名单常在会话起来之后才齐，侧栏不得把「ready 时列表还是空的」当成最终空名单；确认 CLI 与会话都没有模型后才藏下拉。列表顶部有一个固定筛选框（不随条目滚动，无边框 / outline），弹出后自动聚焦，按已加载的名称或 id 做不区分大小写的包含匹配；中文占位为「筛选...」。上下键在当前筛选结果里循环移动高亮（向下超出最后一条回到第一条，向上超出第一条落到最后一条），列表跟着滚到高亮项；回车切换到高亮模型。列表里若有 CLI 的 `auto`，下拉默认选中它（表示不指定，不发给 ACP）。用户后来选了具体模型才写入本机并作用到当前会话；下次打开若仍记得该模型则保持，否则回到 auto。

Agent 调用本地工具时，侧栏用灰色小字展示：左侧 lucide 图标标明 kind（读取 / 编辑 / 执行 / 搜索等），颜色与灰字一致，旁边是工具标题（路径或查询原文保留）。不要做成带边框的卡片。点开后往下展开，入参和返回分别展示：能 `JSON.parse` 的（或本身已是对象）递归拆成段落，不能解析的原文保留。最外层对象若只有一个 key，不显示该 key，只展示它的 value；多个 key 则每项一段，`key` 与 value 用全角冒号「：」连接。value 若还是 JSON 则同样往下拆，内层一律按 KV 段落输出（不再省略单 key）。每深一层，子段落 `padding-left` 增加 `1em`。转成段落后要去掉空行（连续换行压成单次换行，空白段不渲染）。内容最多约 5 行，超出才滚动；不足则盒子跟着内容变矮，不要写死高度。边缘渐变遮罩与过程区相同。进行中标题左侧只显示同色细转圈，不要和 kind 图标并排；转完再换成 kind 图标。标题右侧用全角冒号「：」接上最重要的参数（读取 / 编辑接路径，获取接 URL，执行接命令，搜索接查询），进行中拼上之后结束后也不要拿掉；二次打开历史会话时同样保持这串拼接，不要变回短标题。不要另起一行。整行（含左侧转圈或图标、右侧箭头）单行显示；箭头紧挨文案，不要一开始就居右，只有文案过长被省略时才被顶到行尾，不得折到下一行。流式进行中，若连续多段思考 / 工具中间没有正文，只保留最后一条占同一行，不要一条条往下堆；整轮结束后用户展开「此次执行」才把每一步平铺成各占一行。
7. Agent 请求权限时，默认「默认权限 / Ask every time」：每次 ACP `request_permission` 弹卡（允许一次 / 始终允许 / 拒绝），不自动放行写文件和执行命令。第二档「允许文件修改 / Allow workspace edits」：工作区 cwd 内的编辑/写入自动过，Shell、出网、出目录仍问；不是工作区内所有命令都自动过。第三档「允许工具调用 / Auto-run tools」：工具权限自动选始终允许（没有则允许一次），不再弹卡；不是任何指令都自动过。提问（`cursor/ask_question`）和计划审批（`cursor/create_plan`）前三档都要人点。第四档「允许一切操作 / Allow all」（id `unattended`）：真正无人值守——工具权限按第三档同样自动选始终允许（没有则允许一次），计划卡自动接受，提问卡按确定性规则自动答（每题选第一项；没有选项则交空答案），不把 HITL 卡留在输入框上方等人点。不要把第三档改名叫 Allow all。模式写入本机（`agentMode`）。切到允许工具调用时已弹出的权限卡立刻自动放行；切到允许文件修改只自动放行编辑类；切到允许一切操作时已弹出的权限 / 提问 / 计划卡立刻按上面规则消掉。切走允许一切操作后不再自动过。界面文案要像系统设置：标题短、说明一句、口语，不要翻译腔或营销句。**权限档只表达「拦不拦卡」，不再兼职 CLI 的工作流模式**：不得把「默认权限」映射成某家的 plan、也不得把前三档一股脑映射成 build（那会把权限选择变成隐式模式切换，见第 18 条）。
8. Agent 下发的提问、计划审批、todo 更新，在侧栏可见并可回应。权限 / 提问 / 计划卡片都落在输入框上方（不在输入框下面）；正文同样限高约 9.5 行。Agent 规划的 todo 也不挂在顶栏下，而是同样落在输入框上方：标题栏为「英文 Todo List / 中文 待办项 - 已完成/总数」（如 Todo List - 3/3、待办项 - 3/3），右侧是展开/收起箭头，点击整行标题即可折叠；完成项右侧用带圆圈的对勾 icon（Lucide `CircleCheck`）表示。用户收起后，下次 Agent 再规划出新的 todo（条目 id 或文案变化）时自动展开。新一轮任务一开始就清掉上一轮的 todo；Agent 再列出待办时整表覆盖，不得把上一轮条目并进来。思考过程也是灰色纯文本折叠（「思考 / Thinking」+ 紧挨着的箭头），去掉空行，点开后同样向下展开：最多约 5 行，超出才滚动，不足则贴内容高度，边缘渐变遮罩。Agent 回复里的 ` ```mermaid ` 围栏：`flowchart` / `graph` 用轻量 SVG（`@dagrejs/dagre` 布局，不引入 mermaid 包）画成图；其它类型或解析失败仍显示原来的代码块。不得往 `body` 挂报错 SVG。输入框打字不得让消息列表重跑图或抖动。GFM 表格要画出单元格边框，侧栏太窄时可横向滚动，不能只剩对齐的字。Agent 正文里的链接：若与当前浏览器标签页是同一域名（主机名忽略大小写，`www.` 视为同一站点），点击后在**当前标签**跳转，不要新开标签；域名对不上，或当前没有可用的 http(s) 标签，再新开标签。只处理 `http(s)`。按住修饰键点击一律新开标签，避免把侧栏自己导航走。一轮流式输出**结束之后**，只留下最后一段非思考、非工具调用的正文；思考、工具调用以及它们之前的内容全部折起。收起时是一行灰色纯文本，说明此次执行花了多久（如「此次执行用了 12 秒 / Worked for 12s」）；没有记下时长的旧消息只写「已执行 / Worked」。箭头紧挨文案，不要居整行右侧，也不要做成整行色块或按钮底。鼠标悬停某一行时，只在这一行文案旁出现向右箭头，不要把同条消息里其它工具 / 思考 / 过程行的箭头一起亮出来。整行都可点，但视觉上只是灰字加箭头；点开后箭头改为向下，过程**往下展开**，灰字那一行不要被顶走。过程区只设最大高度、内部可滚，内容不够高时盒子跟着变矮，不要写死高度，避免长过程把后面的正文顶出屏幕。滚动时用混合模式做边缘渐变：还没滚到顶则上方从不透明到透明，还没滚到底则下方从透明到不透明。再点折起。进行中不出现耗时行：连续思考 / 工具（中间无正文）只显示当前最后一条，方便看正在做哪一步。整轮结束后过程先收成耗时行；用户再展开时，这些步骤才按每条一行平铺。若这一轮只有正文、没有过程，就不出现这一行。
9. 用户可中断当前一轮。Cursor CLI 有时在一轮已经成功结束后，把内部流关闭 `RetriableError: WritableIterable is closed` 写成气泡正文，或把 `session/prompt` 收成错误。成功的一轮不得在气泡开头/末尾或顶栏错误条里露出这句；鉴权失败、进程崩溃、真实工具错误仍要可见。不得把 Agent 正文里任意 `Error:` 行都剥掉，只认这一条已知的可重试关流（或等价 ACP 错误），且本轮已经产出过正文或工具结果。
10. 用户可点击已发送的用户气泡，把正文和附件带回输入框修改。输入框顶部左侧提示「正在修改历史消息，重新发送后，该位置后的全部内容将重新生成」（英：Editing a past message. Resending will regenerate everything after this point.），右侧纯文本「取消修改 / Cancel edit」，用主题强调色（深色黄铜 / 浅色钢蓝），带 hover 和点击涟漪。重新发送后该条被替换，其后全部丢掉并重跑。进行中不可点气泡。
11. 当前会话一轮尚未结束时，用户再发送不立刻交给 Agent，而是进入该会话的消息队列。进行中仍可点回形针、拾取和 `@`，方便往队列里组消息。队列列在输入框上方：每行左侧是正文（过长省略），右侧依次是立即发送（Lucide `CornerDownLeft`，回车/换行）、编辑、删除。删除后这条永远不会发出。立即发送会打断当前这一轮，再把**这一条**发出去（不必等到排到队首）：点下去后这条**马上进消息列表**（不能让用户觉得消息没了），随后由 Host 负责「先取消旧一轮、等它收尾、再开始新一轮」——顺序由 Host 定，不靠侧栏猜时机；其余队列项仍按原顺序接着跑。编辑把正文和附件带回输入框；输入框顶（队列下方）左侧提示「正在编辑队列消息，点击发送后会覆盖队列中对应的消息内容」（英：Editing a queued message. Sending will replace it in the queue.），右侧「取消编辑 / Cancel edit」。取消不改队列项。发送时若在改队列项则覆盖该项；否则在进行中入队、空闲则直接发。Agent 本轮结束后自动发出队列最前面一条，再等下一轮结束，直到清空。若用户正在改某条：改的是队首则等他改完点发送再发；改的不是队首则队首仍可按轮次发出。队列按会话分开，不写本机持久化。
12. 有消息后列表仍用 `flex-col-reverse` 做贴底滚动：发送和流式输出时自动跟随；用户往上翻则停止跟随；再滚回靠近底部（约 96px 内）则恢复跟随。内容还没撑满消息区时（空会话刚发出第一条、Agent 还没写很长），消息从**顶部**排，不要贴在输入框上方；只有正文把区域撑满后，旧消息才被顶上去。离开底部超过该距离时，输入框上方浮一层圆形「回到底部」按钮：绝对定位盖在消息上，不占一行、不把列表挤矮。贴底、刚离开几像素、或继续往底外弹性滚动时都不要出现；从底部往上滚时，距底未超过约 96px 保持隐藏，超过后稳定展示，不要先显后隐再显。水平相对输入区居中，上方留约 16px。直径约为原先 56px 的 0.7（约 39px）。默认半透明底 + 轻投影，好和底下的消息分开；hover 时不透明度升高；点击有涟漪。带 tooltip。
13. Agent 完成会落盘产物的任务后，须调用工作区工具 `reportArtifacts`，把本轮产物的本机绝对路径交给侧栏（路径优先 `outputs/...`）。输入框上方（Todo / 权限卡之下、消息队列之上）出现可展开/收起的产物列表：标题「产物 / Artifacts」加条数，点整行标题折叠。每一项左侧是按种类的 lucide 文件图标，中间是文件名（过长省略，悬停看完整路径），最右侧是「打开文件位置 / Show in folder」（仅该项 hover 时出现）。点后由 Host 用系统文件管理器打开所在文件夹并选中该文件（macOS `open -R`，Windows 资源管理器 `/select`，Linux `FileManager1.ShowItems`）；Windows 上路径带空格也必须能选中，不能只弹一个无关的文件夹窗口。若该文件已经不在本机，Host 必须回明确错误（不能静默没反应）。侧栏立刻拿掉该项的打开按钮，换成不可点击的灰色小字「文件已失效 / File missing」（比 `--muted` 再淡一点，无 hover），并把失效记在这条会话产物上，关掉侧栏再打开或再 hover 都不得把按钮变回来。成功打开则保持原行为。同一会话再次调用 `reportArtifacts` **整表覆盖**，不追加，新列表没有失效标记。Agent 若复用同一个命令文件 id 再写一次，侧栏仍要收到这次覆盖，不能只认第一次。空列表不渲染。产物跟会话走，关掉侧栏再打开仍在；新建 / fork 的会话从空表开始。
14. **整个面板都能拖文件进来当附件**：把文件（或文件夹）从系统里拖到侧栏**任何位置**——聊天区、输入区、顶栏、消息列表——都算往输入框附件栏添加附件：不能变成浏览器打开这个文件、跳到别的页面，或什么都不发生。
    - 拖入过程中整块面板盖一层明显的投放提示（虚线描边 + lucide 图标 + 一行中英文案「松开即可添加附件 / Drop to attach」），提示层覆盖整个面板（`fixed` 铺满），不要只盖输入框。离开面板或松手立即隐掉。
    - 松手后每个文件按现有附件语义变成输入框上方的芯片（同一套 `kind` 图标、同一个 `path` 去重、同样可点预览/删除），后续发送、入队、编辑队列项都走原有路径，不另造一套。
    - 拖进来的文件在浏览器里拿不到本机路径，由 Host 复制进工作区 `browser/uploads/` 再按路径当附件（与粘贴截图落 `browser/pasted/` 同一思路）；**文件太大或过多时要明说**（先说明限制，再让用户改用「添加附件」按钮走系统选择器——那条路直接拿路径、无大小限制），不能静默失败。
    - 拖文件夹时把整棵子树复制过去，附件挂**文件夹**路径（Agent 能直接读目录）；内部非文件项（符号链接、不可读项）跳过并不报错。
    - 面板里其它原生拖拽（文本、`draggable` 节点内部拖动）不受影响；只有带 `Files` 的投放才算附件。期间输入框里已有的正文与附件一律不动（不切换当前会话、不抢焦点）。
15. **剪切 / 复制整个输入框时，连同附件栏一起带走**：用户把整段草稿（正文 + 附件）从一个会话搬到另一个会话时，不应该再重新上传一遍附件。
    - **只有全选时才发生**：选区覆盖输入框全部内容（含只剩一个芯片、或只剩一遍回车的情形）时，`copy` / `cut` 才把附件栏一起带上；**部分选中、或输入框里有未选中的内容时，一切跟原生一样**（不做任何多余动作，也不改剪贴板内容）。
    - **粘贴时自动还原**：在任意会话的输入框里 `paste`，如果剪贴板里有这份附带信息，正文按普通文本插入（原有行为不变），附件自动并进当前附件栏（按 `path` 去重，已存在的不重复加）。
    - **`copy` 与 `cut` 都不动原输入框的附件栏**：`copy` 正文和附件都留着；`cut` 只有正文按原生语义被剪走，**附件栏保持不动**——带上附件是为了搬到别处，不代表原处要丢，原处留着同一批附件，用户还能接着用。
    - **不得影响原有能力**：普通复制 / 剪切 / 粘贴、`«@att:…»` 芯片随文本搬运、以及**粘贴图片进附件栏**都保持原样（剪贴板里同时有图片时，图片走原路，不能被这份附带信息抢掉）。
    - 跨应用粘贴（粘到编辑器 / 文档里）只会得到正文文本，不应出现内部标记。
16. **拖入的文件必须真的进附件栏，不许「有提示但没结果」**：投放提示出现只说明浏览器把 `Files` 交给了面板，不等于附件加上了。
    - 从系统拖进来的文件必须走完「读字节 → 交 Host 写进工作区 `browser/uploads/` → 回附件项 → 出现在附件栏」整条链路；任一环走不通都要有能看懂的提示（文件太大 / 一次太多 / Host 没响应 / Host 不认识这条命令 / 文件读不出来），不许静默什么都不发生。
    - 浏览器只给 `File` 对象、不给本机路径，`DataTransfer.items[].webkitGetAsEntry()` 是分辨「文件 or 文件夹」的唯一入口，但**不能只有这一条路**：取文件要有兜底顺序——按 item 拿 entry → entry 读不出来（报错或迟迟不回调）就用同一个 item 的 `getAsFile()` → 一个 entry 都拿不到时用手上现有的 `files` 列表；几条路都空必须报「读不出拖入的文件」，不能一声不啃。
    - **扩展与本机 Host 是两份各自更新的东西**（Host 只在用户跑安装 / 更新 skill 时才换），Host 比扩展旧时，它不认识的新命令会被静默忽略——表现正是「拖进去没反应」。这种版本错配必须在侧栏里说出来（连上时对比 `hello` 带的 `version`），并且任何一条发给 Host 的请求超时后都要报错，不能无限等。
    - 失败提示要指向怎么修，而不是只留一个空附件栏。**文案口径（界面文案通用）**：① 讲功能、讲位置，不讲图标外号（不写「回形针」「attach button」），按钮一律叫它自己的名字（那个按钮就叫「添加附件 / Add attachments」，位置写「输入框底部 / under the input field」）；② 面向用户不出现 `Host` 这类开发词，统一叫「本地桥接程序 / the local bridge」；③ 「拾取元素」是浏览器概念，保留原名不改。
17. **Host 必须应答，不许装死**：侧栏发的每条带 `requestId` 的请求，Host 无论成败都要回一条（成功回结果，失败回 `error`）；**不认识的消息类型也要回一条「不支持」**，让「新扩展 + 旧 Host」表现为一句明确的错误，而不是永远静默。侧栏一侧也要有超时兜底。

18. **会话内可切换 Agent 自己的模式**（plan / build / ask / autopilot / yolo 等，各家命名与 id 都不一样），它与「权限档」是两个互不替代的概念，单独一个下拉：
    - **只信 Agent 广告**：优先读 ACP `configOptions` 里 `category: "mode"`（或 `id` / `configId` 为 `mode`）的选项，没有则回退 `modes.availableModes`。模式名**原样用 Agent 给的 `name`**，不造译名；渲染时只做**首字母大写**这个排版处理（opencode 给的 `build` / `plan` → `Build` / `Plan`），不换词、不翻译；说明用它的 `description`。
    - **只显示真能切的**：广告少于两项（例如某家只有 `default`），或什么都没广告（某家既不带 `modes` 也不带 `configOptions`）时，**整个模式下拉不出现**——宁可没有，也不要摆一个点了没反应的假菜单。这条与「权限档永远显示」不同。
    - **切换要真的写回**：有 mode 配置项时走 `session/set_config_option`，否则走 `session/set_mode`；**只发广告集合里出现过的值**，绝不盲发猜测的 id。
    - **跟随 Agent 自己切换**：Agent 自己换模式（典型是从 plan 退出到 build）后，触发钮必须跟着变，不能停在旧值。
    - **按 Agent 记忆**：用户选过的模式写入本机；下次连同一个 Agent 时若仍在广告集合内就沿用，否则回到 Agent 自己的默认。
    - **连接或切换 Agent 后立刻可见**：模式是在**会话建立**（`session/new|load`）时才被广告的，所以连接一就绪就必须能看到模式下拉——不许需要用户先发一条消息（用户报过这个问题）。
    - **不打扰的回落**：任何情况下都不因为模式切换失败而阻断会话；失败只记日志，控件回到 Agent 实际报的当前值。

19. **思考档位（引擎自己的推理档位）**：跟在模型下拉**右侧**，与模式 / 权限共用同一套 pill 形态。
    - **来源只用引擎广告**：只认 ACP `configOptions` 里 `category: "thought_level"` 的选项（与 `mode` / `model` 同一套机制）。引擎不广告就**不出现**（实测 Copilot CLI 的 ACP 没有这个类别 → 不支持；宁可没有，也不替它猜）。广告了多项时只展示第一项（规范说数组顺序即优先级）。
    - **文案用引擎原名**：pill 显示该选项的 `name`（如 Claude 是 `Effort`），菜单项显示引擎给的 value 名称（`Low` / `High` / `Max`…）——不造译名、不换词，只把首字母大写当排版。
    - **设置**：走 `session/set_config_option`；布尔项按规范带 `type: "boolean"` + 布尔值。只发广告集合内的值。
    - **跟随引擎**：设置返回的完整状态与 `config_option_update` 都以引擎为准——换模型后引擎可能重置该档位，界面必须跟着变。
    - **按 Agent × 配置项记忆**：下次连同一个 Agent、且该值仍在广告集合内就沿用，否则以引擎回报为准。
    - **不带图标、文案优先**：钮是**纯文本**（档位名就是用户唯一要看的信息），宽度跟着内容走、**不设人为上限**；空间真的不够时才单行 `truncate` 省略（**不许换行**），tooltip 始终给「选项名 — 当前值名」。
    - **少于两项不画**（一项等于没得选）。
20. **`model_config` 类选项放进模型菜单里做开关**：引擎广告的 `category: "model_config"` 选项（例如 Cursor 的 `Fast`、Claude 的 `Fast mode`）不单独占输入栏一行，而是排在**模型下拉菜单内**：每项一个小节（选项名 + 引擎给的值名），值逐个列出、当前值打 `Check`，点选即设；布尔项按两项（On / Off）列。宽度不够时不影响主工具栏。
21. **输入框可显式指定本机已安装的 Skill**（`/` 探测菜单）：
    - **入口**：`@` 钮右侧是 `/` 钮（Lucide `Slash`，与其它工具栏钮同一个 `COMPOSER_ICON_PX`）。点钮把光标移到输入区最前面并插入一个 `/`，同时打开探测菜单；在输入框里敲 `/`（行首或空格后，与 `@` 同一套触发规则）也能唤起。Esc、删光 `/`、光标移出触发区都关闭，与 `@` 菜单一致。
    - **菜单形态**：与 `@` 菜单同一套定位（跟光标、优先出现在上方、与视口四边 16px 安全距离、空间不够就内部滚动）与同一套键盘（上下循环高亮、回车只插入不发送、Esc 关闭）。**搜索框固定在菜单最底部**（不随条目滚动、无边框 outline、弹出即聚焦），placeholder 沿用 `@` 菜单的说法（中文「筛选...」）；菜单打开期间在输入框里继续打字即为搜索词。
    - **列表内容**：只列本机全局已装、可被本地 Agent 访问到的 skill（`~/.claude/skills`、`~/.cursor/skills`、`~/.codex/skills`、`~/.agents/skills`、`~/.cursor/skills-cursor`、`~/.stepclaw/skills`），按名称排序；同名只留一条（优先 Claude 目录）。每项左侧按来源的 lucide 图标、中间是**别名**、右侧来源小标签。目录里没有 `SKILL.md`、或 frontmatter 里既无 `name` 也无可用标识的，直接跳过。
    - **随选中展示详情**：键盘高亮或鼠标 hover 到某项时，在列表**右侧**用二级面板展示该项详情：顶部是别名、（别名与 name 不同时）`/name`、来源、本机路径，下面是 `description` 全文（可滚动，不截断）。列表最小 224px、详情 240px，弹层整体加宽（仍受视口 16px 安全距离限制）。**侧栏太窄（< 496px）放不下两列时，详情折到列表下方**：同一弹层内上下两段（单列宽度回到 256px），详情区可滚动，搜索框仍在最底部。鼠标 hover 与键盘高亮冲突时，**后发生的那一个覆盖**。
    - **别名与名称**：别名取 `SKILL.md` frontmatter 的 `display_name`（如 `水产市场`），没有则用 `name`；`description` 只当详情文案与搜索词，**不当别名**（实测普遍 400–900 字符，是写给模型看的详细说明）。
    - **搜索**：不区分大小写，同时匹配 `name`、`display_name` 与 `description`（中英文名、中文说明都能搜到）；匹配字符在名称上换成主题强调色，与 `@` 菜单一致；无匹配就空列表，不塞假条目。
    - **插入位置**：无论光标在哪唤起、选中哪个，芯片**一律插到输入区最前面**；连选多个就按选择顺序在最左依次累积（`/a` `/b` 正文）。同一个 skill 选两次只留一个。芯片与 `@` 芯片同一套样式（行高对齐、最大宽 200px、超出省略、点击落到芯片后方、容器内禁止划选），内容显示 `/name`（真实 `name`，不是别名）。
    - **发给 Agent 的形态**：用户气泡里按芯片渲染；发给 Agent 的正文在最前面写成 `/name`（各家 CLI 的原生 skill 调用语法），而且这一段走单独的字段**拼在整个提示词的最前面**——包括 Host 自己加的「当前标签页」信息之前（斜杠调用只有落在最前才会被 CLI 当 skill 用），不指望侧栏自己能抢到头几位。另外附一段说明（告诉 Agent 用户显式指定了哪些 skill、它们的本机路径），兜底不认识斜杠语法的 CLI。
    - **新装的 skill 不用重连**：打开探测菜单时若列表超过 5 分钟没刷新过，先重扫一次（只读 `SKILL.md` 头部，成本极低）。

### 工作区与会话

1. 所有页面共用一个工作区：`~/.opensider/workspace`。页面工具、快照、命令文件不随聊天会话切换。Host 每次启动 / 安装都会确保存在 `outputs/`（0755）。用户会打开的任务产物（html / pdf / md / 图片等）应写在 `outputs/`（相对工作区 cwd），不要落在工作区根目录和 `AGENTS.md`、`browser/` 混在一起。草稿、临时文件可以放别处。这是工作区约定，**不**拦截 Agent 的 Write / Shell。写完后仍须 `reportArtifacts`。
2. 聊天是多会话。侧栏可新建、切换、重命名、置顶、删除会话。会话卡片上有置顶、重命名和删除按钮，与标题同一行，仅 hover 时出现；置顶后进入列表最上方的「置顶」分组，取消置顶则回到按时间的分组。进行中的会话左侧用六点字符 spin 代替圆点。手动改过的标题不会被后续消息覆盖；空标题和默认的「新会话」/「New Chat」不算手改，发出消息后仍会换成首条正文的一行标题（不按字数截断）。删除前用非阻塞 popover 二次确认（不是 `window.confirm`、不铺全屏遮罩）。弹层锚在删除按钮旁，与视口四边保持 16px 安全距离，空间不够则翻边或缩短，标题过长省略。Esc / 点外面取消；确认后才真正删除。删掉当前会话会切到另一条；删光则自动新建一条。关掉侧栏或换标签不会自动新建。
3. 当前选中的会话、每个会话的标题和消息历史，关掉侧栏再打开仍然在。Host 重启后尽量 `session/load` 回对应的 ACP 会话；失败则新建 ACP 会话，界面历史仍保留，下一条用户消息会带上此前的摘要上下文。**刷新扩展（或重启 Host）之后第一次打开侧栏，要自己连上上次选的那家 Agent**：模型列表与推理档位都得自动就位，不许停在空白等用户手动切一次 Agent 才醒过来。完整侧栏状态（语言、主题、权限模式、选中的 Agent 模式、选中的 Agent/模型、会话列表与每条消息、抽屉开合与宽度、引导是否完成）除了写 `chrome.storage.local`，还要镜像到本机 `~/.opensider/ui-state.json`。卸载或刷新扩展会清掉 `chrome.storage`，**不得**因此丢掉会话：Host 连上后若本机镜像比扩展存储新（或扩展是空的），用镜像灌回侧栏。空状态不得覆盖已有镜像。镜像灌回与落盘**不得因历史体积失效**：状态超过 Native Messaging 单帧上限时按分片传输（收发两端各自重组），任何体积的镜像都要能灌回；扩展本地热缓存写失败（如配额）也不得阻断向 Host 的镜像写入。ACP 工作区里的会话还在，但不得把 `session/load` 回放的整段 prompt 画成一条用户气泡。已经坍成一条的本地记录，打开时尽量按 `User:` / `Assistant:` 拆回多轮，并去掉 `[Current tab]` / fork 包装前缀。用户气泡和会话标题也不展示这行环境前缀。
4. 用户可从任意一轮 **Agent 回复** **fork**（用户气泡下不放）：原会话不动，新会话复制该回复及之前的消息，之后独立往下聊。不做 checkpoint。中文 tooltip 为「从此处复制新会话」，英文为 Fork from here。
5. Agent 回复底部一行只在 hover 时出现：左侧灰色字说明此内容由哪个模型生成（如「由 Auto 生成 / Generated by Auto」），右侧无边框 **复制**、Fork 与 **重新生成**（刷新 icon）。复制只写入这一轮可见正文的 Markdown，不含已折起的「此次执行 / Worked」过程（思考、工具调用、过程前的正文）。点复制成功后，Copy icon **原地**换成对勾（Lucide `Check`），约 1.5 秒再切回；成功反馈期间这一行保持可见，不必一直悬停。本轮还在流式输出时，最后一条回复上这一行无论是否 hover 都不出现，结束之后才可以。重新生成会丢掉该轮及之后的 Agent 回复，用同一条用户消息再跑一遍，不另开会话。中间轮次重跑会截掉后面的对话。中文 tooltip 为「复制 / 已复制 / 重新生成」，英文为 Copy / Copied / Regenerate。用户气泡上方间距是普通消息间距的两倍（24px），跟上一轮 Agent 回复拉开。
6. 多个会话可以同时跑不同任务。某一轮还在进行时，仍可新建会话或切到别的会话继续发；流式更新必须写回**发起这一轮的会话**，不得因为后来选中了别的会话而写错地方。**任何流式更新、回合结束、权限 / 提问 / 计划、浏览器工具命令与结果，都按事件自带的会话标识精确写回它所属的会话；找不到归属的事件宁可丢弃，也不许落到当前选中的会话**。会话与 ACP 会话的绑定按「请求-响应一一配对」维护：一次请求没回、或一次回应对不上请求，都不得让后续绑定错位（错位会把旧任务的内容串进新会话）。切走之后，输入框的进行中态、停止钮和权限/提问/计划卡片只属于当前正在看的会话：回到那个会话才能看到并处理。对某个会话做 fork、重新生成或改历史再发时，只在**该会话自己**正在跑时拒绝。重命名随时可以。删除正在跑的会话会先取消这一轮再删。

### 日志与诊断

1. `~/.opensider/host.log` 是排障入口（doctor 与 skill 都按它判断 Host 有没有被拉起来），但**不能无限涨**：按大小和时间切片轮转——单文件超过上限（约 2MB）或跨过本机日期就切一份出去，只保留最近几份，最老的删掉。
2. 正在写的那份**路径与文件名不变**（仍是 `~/.opensider/host.log`），这样既有文档、README 表格、skill 里的 `tail -n 12 ~/.opensider/host.log` 全部继续有效；切出去的历史片才带时间戳。
3. 切片对调用方透明：写日志的地方不需要关心轮转；切片失败（例如文件被别的程序占着改不了名）不能影响当次写日志，也不能变成每写一行就重试一次。
4. 历史片有上限，避免「轮转本身把磁盘写满」。

### 语言

1. 界面只做中英两种。**首次安装**（本机还没有语言偏好）时跟浏览器 UI 语言：中文（`zh*`，含 zh-CN / zh-TW 等）用简体中文，否则英文。之后以用户在设置里选的为准，不要每次打开再去读浏览器。
2. 语言在右侧抽屉「设置」tab 用下拉切换 English / 中文。界面中英都不使用衬线体。
3. 语言选择写入本机，下次打开仍是上次的选择；打开侧栏第一帧就要用上次的语言（或首次安装时探测到的语言），不要先闪英文再切回去。
4. Agent 工作区说明（`AGENTS.md`）保持英文，不随界面语言切换。

### 主题

1. 界面有浅色、深色两套，另可跟随系统 `prefers-color-scheme`。**首次安装**（本机还没有主题偏好）时默认「跟随设备」，与浏览器外观设为跟随系统时一致；实际明暗跟 `prefers-color-scheme`（Chrome 的浅色 / 深色 / 设备都会反映到该查询）。之后以用户在设置里选的为准。
2. 主题和语言都在右侧抽屉「设置」tab 里用带灰色 Prefix 的下拉切换，不在顶栏循环点 icon。主题三项：浅色模式 / 深色模式 / 跟随设备（英 Light / Dark / Device）。
3. 主题选择写入本机，下次打开仍是上次的选择；打开侧栏第一帧就要用上次的主题（或首次安装时的跟随设备），不要先闪默认深色再切回去。跟随设备时系统改明暗，侧栏立刻跟着变。
4. 浅色是柔和、有层次的中性浅灰（浅灰画布 + 近白抬升面 + 钢蓝强调），不要暖黄纸色，也不要发脏的蓝灰底。正文、muted、链接/强调色、用户气泡、代码块在两套主题里都对背景保持足够对比，禁止浅色主题继续用深色专属的浅字或深底。

### 页面感知与操作

1. 浏览器**活动标签**一旦变化，扩展必须实时更新「当前页」：用户点击其它标签、关掉当前标签后浏览器激活另一张已打开的标签、窗口获得焦点、标签在窗口间移动 / 挂接 / 分离，或当前页 URL 变化。关掉当前标签时不得继续把已关闭的 tabId / URL 当作当前页。每次活动标签变化都要同时刷新工作区 `browser/current.json`（以及 `snapshot.md` / `interactive.md`）和 `browser/tabs.json`，好让下一条用户消息的 `[Current tab]` 行、侧栏页面状态、以及 Agent 读到的工作区文件都指向新的活动标签。同域链接点击仍按原规则在当前标签跳转，不另开标签；本条管的是标签身份 / 当前页，不是页内链接。**这条能力来自扩展的 service worker（`chrome.tabs` / `chrome.windows`）与隔离世界的内容脚本，不依赖任何主世界注入**：不管用户有没有在用 OpenSider、页面上有没有被注入过钩子，`tabs.json` / `current.json` 都必须实时反映「所有已加载的标签」和「当前激活的那一个」。
2. 侧栏不再用 banner 或顶栏 favicon 展示当前页标题与 URL。Agent 正在执行页面命令时，不要把该方法名挂在顶栏：它是工具调用提示，写进当前这一轮对话正文（和其它 tool-call 同一套灰字折叠），不是 Todo List。
3. 每条用户消息在发给 Agent 时附带一行当前页上下文（标题 + URL），界面里只显示用户自己输入的文字。
4. 内容脚本向页面注入白名单方法；批处理另可由 SW 执行 `runScript`。Agent 通过工作区命令文件调用，不走 MCP。扩展刚刷新、标签在注入前就打开、或页面（如 YouTube）在 `document_start` 之后内容脚本还在异步加载时，页面读取 / 操作 / 快照必须先补注入并等到页面 API 就绪，不能因为没有消息接收端就让 Agent 读到空的 `snapshot.md` / `interactive.md`，或只看到 Chrome 的 `Receiving end does not exist`。命令无论成败都要写出 `browser/results/<id>.json`；失败错误要能看懂（系统页、未注入、超时分开说）。
5. **读取**：元信息、正文、选区、链接、标题大纲、按选择器取文本 / 属性 / 值、列出匹配元素、判断元素是否存在。另可列出当前 Chrome 里所有普通窗口和标签（`tabId` / `windowId` / 标题 / URL / 是否当前 / 是否系统页）。**交互快照**（`getInteractive` / `browser/interactive.md`）列出当前页可见的可点、可填控件：编号、角色、标签、当前值、占位、是否在视口内。这是填表和点击的主入口，不要让 Agent 只靠正文纯文本或猜 CSS。
6. **操作**：点击、双击、悬停、聚焦、填写、追加输入、清空、下拉选择、勾选、按键、滚动、等待元素、导航、前进 / 后退 / 刷新。另可按 `tabId` 切换到指定标签（并聚焦它所在窗口），用 `openTab` 新开 http(s) 标签（不要用 `navigate` 覆盖当前页），用 `closeTab` 关闭标签，或把若干标签抽到新窗口 / 搬进已有窗口。**一次填多字段**用 `fillForm`（按编号 / 标签 / name 匹配），避免一格一格猜。**离开页面前**须先 `getUnsavedChanges`：若页面有用户未提交的编辑，不得直接 `navigate` / `reload` / `goBack` / `goForward` / `closeTab`。过程中只是要去别的页拿信息 → 一律 `openTab` 新开，保住当前页；用户明确要求关掉或覆盖当前页 → 先用交互式提问卡（`cursor/ask_question`）说明风险并等确认，确认后才可带 `args.force=true` 执行。未确认的覆盖/关闭会被扩展拒绝并返回未保存摘要。**批处理 / 重复 DOM 操作**可用 `runScript`（`args.code` 为 async 函数体，可选 `world: MAIN|ISOLATED`）在页面里一次跑完，避免逐条 click/fill。
7. **动手前先核对**：自动化开始前先读 `interactive.md` / `snapshot.md`（必要时再截图），对照用户描述。若页面结构、文案、控件与用户说法不符，或目标不明确，先用提问卡确认，禁止瞎点蛮干。能判定为批处理（多行表格、批量勾选、批量导出等）时，摸清选择器后再优先 `runScript`，而不是循环发几十条单步命令。
8. **视觉**：截当前视口，或把指定元素滚入视口后截该元素。图片落到工作区文件，供 Agent 用视觉理解布局、对照文案、规划下一步点击。有交互快照时视觉是补充，不是填表的第一步。
9. 定位元素优先用交互快照里的 `args.index`（从 1 起），其次是关联标签（`args.label` / `args.name` / 可见文本会落到对应控件，而不是落在 `<label>` 或标题上），再次才是 CSS 选择器；可再加 `nth`。点击、填写、悬停前先滚到元素，再把页面上的 **Agent 光标**（参考 page-agent：渐变箭头 + 点按涟漪）滑到目标中心并短暂高亮该控件。光标不拦截页面事件，也不挡我们自己的点击命中。
10. 填写控件时派发完整的 pointer / beforeinput / input / change，并用原生 value setter，以便 React / Vue 等受控输入能收到。原生 `<select>` 按 option 的 value 或可见文本匹配；自定义下拉（combobox / listbox）先点开再点选项。contenteditable 先合成事件，失败再 `execCommand('insertText')`。
11. 导航只允许 `http(s)`。操作完成后刷新当前页快照，并重写交互控件列表（编号可能变）。命令结果里带上新的交互列表，避免 Agent 拿着过期 index 继续点。
12. Host 启动、会话建立时，工作区已写好 `AGENTS.md` 和 `browser/tools.json`，并确保 `outputs/` 存在。Agent 在插件连上的第一时刻就能读到全部页面方法（含截图、标签/窗口、交互快照、`runScript`）以及产物回传 `reportArtifacts`，不必等用户再说明。打开的标签实时写在 `browser/tabs.json`，当前页控件写在 `browser/interactive.md`，Agent 先读这两份再动手，不要猜 tabId 或 CSS。写完会给用户看的文件后必须再调一次 `reportArtifacts`（路径优先 `outputs/...`）。
13. 以下页面不注入、不抓取、不操作、不截图、不跑 `runScript`：`chrome://`、`chrome-extension://`、Chrome Web Store。仍可出现在 `tabs.json` 里并允许 `switchTab`（只是切过去看），但不能对这些页跑页面读/写/截图/脚本。
14. 页面自动化默认执行，不再逐步弹权限（用户装这个扩展就是为了让 Agent 动手）。本地文件写入和 Shell 仍走 ACP 权限条。
15. **浏览器原生 UI 的感知与受控代答**：页面弹 `alert` / `confirm` / `prompt`、调 `print()`、开 `window.open()`、或点 `<input type=file>` 唤系统选择器，都算「原生 UI 状态变化」，Agent 必须能感知，并能在明确授权下代答：
    - **感知范围＝Agent 真正碰过的标签页**：这层只能从页面的主世界注入，而往主世界注入就等于改掉页面能读到的原生 API（`Function.prototype.toString` 不再是 `[native code]`、`HTMLDocument.prototype` 上多出自有访问器、`window` 上多出全局），是站点反爬 / 完整性校验一眼能看出来的指纹，实测会打坏「加载期就做环境自检」的站点（抖音等的播放器初始化即属此类）。所以**只在侧栏开着、且 Agent 已经触及这个标签页时才注入**（`chrome.scripting.executeScript`，见 TECH_DESIGN「主世界钩子的注入时机」）：用户没在用的标签页一律不注入、不留任何可探测的改动。
    - **感知内容**：注入后包住这几个入口，每次触发都记一条事件（kind、message、defaultValue、frame url、时间、是否发生在 Agent 命令执行中、是否被代答、答案），写进 `browser/native-ui.json`（最近 50 条，Host 落盘），并附在**触发它的那条命令结果**里（`data.nativeUi`）——Agent 点一下就知道这一下弹了什么，不用再去翻文件。
    - **边界（不许吹）**：注入之前——页面刚打开、Agent 还没碰过它的时候——弹出的原生对话框不会被记录，也不会被代答；`getNativeUi` 只见证从注入那一刻起的调用。做不到「全站常驻感知」，因为代价就是上一条说的指纹。
    - **代答（默认不做）**：默认只观察、不改行为：真弹窗照旧由用户点，我们只记录事件与用户给出的答案（`confirm` 的 true/false、`prompt` 的文本都拿得到）。Agent 需要用 `setDialogPolicy` 显式切到 `answer` 模式（可带 `expiresAt`，默认 120s）才由我们同步代答：`alert` 直接关掉、`confirm` 按策略返回 true/false、`prompt` 返回策略文本、`<input type=file>` 的 `click()` / `showPicker()` 在代答模式下**不弹系统选择器**（它会把整页 JS 线程卡死）只记事件——这是 Agent 能在「点一下就要求选文件 / 确认」的站点上继续干活的关键。
    - **同步约束**：`confirm` / `prompt` 是同步 API，代答必须在调用当刻就返回，所以策略是**提前**推给主世界缓存的（不存在「挂起等 Agent 事后答复」这种做法）；`answer` 模式会过期，过期即回 `observe`，避免用户之后正常浏览时的弹窗被静默吞掉。
    - **可读的 UI 状态**：`getNativeUi` 同时返回当前标签的权限状态（`navigator.permissions`：geolocation / camera / microphone / notifications / clipboard-read / clipboard-write）、`visibility`、`fullscreen`、是否注册了 `beforeunload`，让 Agent 知道「点下去会不会弹系统授权框」。
    - **边界必须说清楚，不许吹**：Chrome 扩展 API 看不到也点不到真正的浏览器 / 系统 UI——权限授权框、HTTP 认证框、下载气泡、系统文件选择器窗口、原生右键菜单、证书警告。只有 `chrome.debugger`（CDP：`Page.handleJavaScriptDialog` / `Page.fileChooserOpened` + `DOM.setFileInputFiles` / `Browser.setPermission`）能看到并操作，代价是「正在调试此浏览器」横幅、与 DevTools 互斥、以及 `debugger` 权限（会多一条权限提示）；v1 不做，只在 TECH_DESIGN 里备着。
16. **面板开着的时候，页面必须保持「活着且可见」**：浏览器窗口被别的窗口盖住、被最小化、或标签不在前台时，Chrome 会让页面变成 `hidden`（`document.visibilityState === "hidden"`、`hasFocus()` 为假、`requestAnimationFrame` 不再回调、定时器被降频到 1/秒、5 分钟后进一步降到 1/分钟）。很多站点据此暂停自己（懒加载、动画组件、把点击挡在「页面未激活」的遮罩后面），Agent 的点击和脚本就会卡住——用户看到的是「浏览器被遮住的时候点不动」。要求：
    - **只要侧栏开着**（面板连着扩展），Agent 正在操作的那个标签页就要被强制成「可见 + 有焦点」：页面读 `document.visibilityState` 得到 `visible`、`document.hidden` 为 `false`、`document.hasFocus()` 为 `true`，并且**收不到** `visibilitychange` / `blur` / `pagehide` / `freeze` 这些「你被藏起来了」的事件（页面因此不会自己暂停）。这层同样是主世界注入，注入范围与第 15 条同一条规矩：**只装 Agent 触及的标签页**，其它页面一点都不动。
    - 页面被真的隐藏时 `requestAnimationFrame` 不会回调，要让等帧的页面 / 脚本继续动：改成定时器回退（约 16ms）。
    - **不抢用户焦点**：不得为了这个把窗口提到最前、取消最小化、或切到别的标签。用户该干嘛干嘛，页面在后台也照常能操作。
    - 覆盖的标签是「Agent 正在动的那一个」：面板打开时当前活动标签，以及之后每条页面命令 / 当前页快照触及的标签（Agent `openTab` / `switchTab` 换页后同样要跟上）。
    - **侧栏一关就还原**：所有被改过的状态（可见性 / 焦点 / 帧回退 / 防丢弃标记）都要恢复成浏览器本来的行为，不留下常驻的 hack；`hidden` / `visibilityState` / `hasFocus` / `document.onvisibilitychange` / `requestAnimationFrame` / `EventTarget.prototype` 的监听方法都要回到原生实现（`requestAnimationFrame` 等入口无法恢复成「从没被碰过」的同一性，但行为必须与原生一致）。页面刷新后钩子随页面消失，重新触及时补注入。
    - 顺带：被强制期间不允许多余行为——不改页面 DOM、不拦用户自己的交互、不加可见元素；`getNativeUi` 里的 `visibility` 要反映**强制后**的值（Agent 不该看到 `hidden` 而以为自己不能动手）。
    - **边界**：这层强制发生在**页面可见的 API 层面**，让页面自己认为可见。Chrome 自己的后台降频 / 渲染降级无法用扩展 API 取消（只有 `chrome.debugger` 能做到，代价同第 15 条），所以后台执行可能比前台慢；不得宣传成「强制前台渲染」。
17. **动作之后要自己看局面，不能凭「点了没反应」就继续试**：Agent 点一个按钮 / 提交一个表单后，页面经常不是在原地变，而是弹出一个**页面自己的模态框、抽屉、浮层、下拉面板或全屏遮罩**（不是第 15 条那种浏览器原生弹窗）。这种变化必须在 Agent 的视野里，否则它会把「弹了模态框」当成「点了没反应」，重复点、点别的、或者去猜，最后告诉用户「这个按钮不管用」。要求：
    - 提供一个能直接问当前页面「有没有盖在上面的东西」的页面方法（角色 `dialog` / `alertdialog`、`aria-modal`、`<dialog open>`、高 `z-index` 且 fixed/absolute 盖住可观察面积的层都要认出来，包含开放 Shadow DOM 与同源 iframe），回每条的角色 / 可读标题 / 正文摘录 / 层级 / 盖住的范围，以及「页面被遮住了」的迹象（背景被置 `inert` / `aria-hidden`）。
    - 每条**页面的操作类命令**（click / fill / select / check / press / 滚动…）执行完，结果里直接带上这个快照（只在**出现或变化**时带，避免噪音）——不是弹窗时什么都不加。它要和已有的原生弹窗事件（`data.nativeUi`）一起看：一个是页面自己的层，一个是浏览器弹的窗。
    - 命中过的快照同时落盘 `browser/overlays.json`，Agent 随时可读；没有浮层时写空表，不留上一次的旧值。
    - `AGENTS.md` 里要写清这套流程：动作后先看「预期变化有没有发生」→ 没发生就不要重复点，先查页面浮层、再查原生弹窗、再重新取一次交互列表（编号可能已经变了）、看 URL / 标题 / 标签页有没有变，必要时用 `waitFor` 等具体元素；同一个控件连续点两次没反应就停下来换思路或问用户。
18. **不给没在用的页面留痕（硬约束）**：扩展在**主世界**（页面自己的 JS 世界）动过的东西，页面都探测得到——`Function.prototype.toString` 不再是 `[native code]`、`HTMLDocument.prototype` 上多出自有的 `hidden` / `visibilityState` / `hasFocus`、`window` 上多出固定名字的全局，全是站点判断「环境被篡改」的现成指纹；而这类判定一旦命中，站点常见的反应就是拒绝初始化自己的重型组件（播放器、编辑器）。因此：**主世界注入只允许发生在「侧栏开着 + Agent 已经触及该标签页」的页面上**，注入后也不得借机改别的东西；用户没在用的页面必须与干净浏览器**逐项一致**。隔离世界（内容脚本默认世界）页面看不见，可以按需在 `document_start` 注入。注入过的标签页被释放（侧栏关闭）后要还原到与原生行为一致，**而且之后再次触及必须能重新装上**（钩子得是可重复执行的经典脚本，不能是一次性求值的模块）；页面自己抢先认领钩子时，扩展要能识别并自愈，不能让 Agent 就此失明。
19. **Agent 标签接管（借用 / 收回）——「互不影响」是硬承诺**：任务运行时，Agent 的动作不改变用户的视野与节奏；用户的动作（切标签、切窗口、操作页面）也不改变 Agent 正在操作的对象。
    1. **目标锁定**：用户每次发出消息时，把当时所在的标签记为该会话的锚点，并把「省略式命令」的路由目标指回它。Agent 的读 / 写命令默认落在路由目标上；开始写操作时**自动接管**（借出）该标签，此后命令只落在接管的标签上——用户切标签、切窗口都不改变 Agent 的操作对象；写命令落在别的标签时，路由目标跟随过去（Agent 去哪干活，接下来的省略式命令就跟到哪）。
    2. **进入其它标签要用户点头**：读 / 写 / 切换非锚点、非自建、未接管的用户标签，一律返回 `borrow_required`，并在侧栏弹一张借用卡（标签标题 + 域名）。**答完卡不用再打字**：不论「允许」（Agent 重试即可）还是「拒绝」（一段时间内静默拒绝、不再弹卡骚扰），侧栏都**立即打断**该会话正在跑的那一轮，并以**通道消息**把 Agent 带回正轨（允许 → 继续刚才的任务；拒绝 → 别重试、告诉我怎么办）。这条消息只发给 Agent，**不进侧栏的消息记录**——实时与历史都不显示，也不参与重新生成 / Fork 的「上一条用户消息」（它在 Agent 自己的会话历史里保留）。**档位即授权**：输入框右下角的权限档位对借用卡生效——`auto`（允许工具调用）/ `unattended`（允许一切操作）下不再弹卡、直接接管（Agent 那条命令直接成功）；`ask`（默认权限）/ `workspace`（允许文件修改）维持弹卡。显式意图优先于档位：用户拒绝过的标签在冷却期内仍 `borrow_denied`；别的会话持有的标签仍 `borrow_held`；档位放行**不写访问记忆**（切回询问档后仍会重新问）。收回不留冷却——收回后再次进入照常走档位（询问档弹卡 / 自动档放行）。切换到自动档时若还有未答的卡片，按「允许」处理（授权 + 通知 Agent 继续）。
    3. **收回随时可用**：状态卡常驻「收回」，收回立即生效——接管、记忆一并释放，标题标记移除，**不留冷却**：之后 Agent 再次需要这些标签时照常走闸门（询问档弹卡、`auto` / `unattended` 档直接放行），而不是默认被拒。只有「拒绝」过的标签保留一段静默拒绝期（明确错误原因、不再弹卡骚扰）。
    4. **无打扰承诺**：除用户明确要求，任何命令不得改变焦点窗口与活动标签。`openTab` 一律后台打开（落在目标标签旁、不激活、不切窗口）；`switchTab` 只保留「把某个标签展示给用户」的语义，Agent 选择工作对象必须用命令里的 `tabId`。截图是唯一例外：目标不在前台时临时激活、拍完**守卫式还原**（用户在中途切走就不再动它）。
    5. **后台可操作**：被接管的标签不在前台时，读 / 写、弹窗观察与代答照常；受前台限制的能力返回明确原因（`needs_focus` / `needs_visible`），不得表现为超时。接管期间禁止浏览器自动回收该标签（`autoDiscardable`）；仍被回收时结果里写明状态。
    6. **状态可见**：**侧栏输入框上方**常驻状态卡，与 TodoList / 待发消息同一族样式（圆角卡片、`--panel-2` 底、`--line` 描边），随输入区一起堆叠：有命令在跑时显示「正在操作「<标题>」」（动态指示），空闲时显示「已接管「<标题>」」，多于一个标签给计数；右侧是「收回」。被接管的标签（含 Agent 自建）在**标签标题前加状态前缀**（中文界面「[接管中]」、英文界面「[Agent]」，按浏览器界面语言；不用符号点），不在前台也能看见；收回 / 释放后移除。**我们自己的一切界面与文件都剥掉该前缀**——状态卡、借用卡、@ 提及菜单，以及 `current.json` / `tabs.json` / 页面读取结果里的标题都是干净的原标题（`stripControlMark`）。另外，顶栏标题与左右控件之间保持相等的安全间距（不因某一侧控件变宽而被挤到贴边或重叠）。
    7. **生命周期：回合结束即归还**。每个回合结束时（`turn.end`）自动释放接管——标题前缀与 banner 一并收起；「自己开的标签」和「用户批准过的标签」记入**访问记忆**，再次进入免审批、静默重新接管；其它标签下次仍先询问。标签被关 → 自动清理；浏览器重启 → 全部清零；会话删除 / 用户收回 → 接管与访问记忆一并释放（都不带冷却）。30 分钟无命令的兜底清理保留（惰性）。
    8. **多会话**：一张标签同一时刻只属于一个会话；另一会话解析到它时明确拒绝（`borrow_held`），不做静默抢占。
    9. **不做的**：独立 Agent 窗口 / 标签组 / 停车位窗口；popup 自动改道；逐操作确认；「接管 = 可关闭」（关闭仍走未保存拦截与用户确认）。

20. **划词工具条（选中文字就能翻译 / 搜索 / 引用）**：在网页上划选一段文字时，在选区附近浮出一条横向工具条——左端是我们的品牌标记，右端三个「图标 + 文案」按钮：**翻译 / 搜索 / 引用**。它是**被动出现**的辅助入口，只在「侧栏已展开 **且** Agent 已正常连接」时生效；任一条件不成立就完全不出现（页面上不留任何痕迹，已弹出的要立刻收掉，在飞的请求一并取消）。
    - **触发**：选区稳定约 120ms 后出现（拖动过程中不乱飞）；空选区不出现；选区落在输入框 / 可编辑区域里不做（不干扰站点自己的编辑交互）。
    - **长度上限**：选中文本**超过 200 字（按 Unicode 码点算，不是 UTF-16 长度）就不出现工具条**——超长选区这个功能直接不支持，不提示、不降级。
    - **位置**：默认贴选区下方 8px；下方空间不足则翻到上方；左右按 **8px 安全边距**夹在视口内——任何情况下整条工具条都要完整落在视口里。
    - **跟随与隐藏**：滚动 / 窗口缩放 / 进全屏都重新定位；**选区整个移出视口就随之隐藏**（部分可见则继续夹在视口内）；Esc、点空白处取消选中、选区内容变化、门控条件转不成立、页面导航，都立即关闭。
    - **翻译**：点「翻译」在工具条下方弹出结果层：进行中 → 译文；失败给一行错误 +「重试」。目标语言取**浏览器语言**（不是界面语言）。**不进入当前会话的上下文**（见 TECH_DESIGN 的隐藏通道）：这次划词只服务于这一次翻译。
    - **搜索**：点「搜索」在工具条下方弹出结果层，内容是把选中文本交给 Agent 做关联搜索后返回的 **Markdown**（渲染与侧栏同一套），要求它**真去检索**、优先用百科类来源、并给出来源链接；**搜不到就明说，不许编**。同样**不进入当前会话的上下文**。
    - **只显示结论**：结果层不得出现 Agent 的过程叙述或思考（「我先去搜一下…」这类），也不得先出现一段中间正文、再被最终那条刷掉。发出去的提示词直接要求「只要结论、不要前言、不要过程叙述」；Host 另外按**工具调用**切一刀（调用之前累积的正文不交出去），而且**搜索整轮都不推增量**——这期间结果层就停在「搜索中」，只在结束时一次性给最终那条正文；翻译没工具可调，照常逐字流出。
    - **结果层高度**：正文最少 10 行、最多 20 行（标题行与内边距另计）；内容不足 10 行由内容撑高，加载中用 10 行占位（避免先小窄条、再跳成一大块），超过 20 行由结果层内部滚动。不按视口比例铺满。
    - **方向与溢出**：优先放在放得下整条的那一边（上下都得试），两边都放不下就选空间更大的一边——**允许超出视口**（结果层自己滚动、页面也能滚，用户照样能看全，不为此把工具条挤到看不见的地方）。只有工具条时的首次布局必须让它完整可见；结果层展开后按实际空间重算方向。放在选区上方时，结果层摆在工具条上面，工具条始终紧贴选区那一侧。
    - **引用**：点「引用」把选中文本以芯片形式插到侧栏输入框的**光标处**；输入框没聚焦时插到文本末尾。芯片与附件 / 技能芯片同一族（同高、同圆角、同底色），内容是 `Quote` 图标 + 用排版引号包住的原文（引号只是展示，芯片里保存的原文一字不改），tooltip 给引用全文；发给 Agent 时展开成 markdown 引用块（`> 原文`）。这条消息发出去后，用户气泡里显示的也是同一个芯片。
    - **复制**：翻译与搜索结果层都带「复制」按钮（复制译文 / 搜索结果的 Markdown 原文），点完显示一行「已复制」。
    - **文案**：按钮「翻译 / Translate」「搜索 / Search」「引用 / Quote」；三个 aria「翻译选中文本」「搜索选中文本」「引用到输入框」（英文 Translate selection / Search selection / Quote into composer）；进行中「翻译中… / Translating…」「搜索中… / Searching…」；失败「翻译失败 / Translation failed」「搜索失败 / Search failed」+「重试 / Retry」；结果层标题「翻译 / Translation」「搜索结果 / Search results」；复制「复制 / Copy」「已复制 / Copied」。发给 Agent 的提示词原文见 TECH_DESIGN。工具条文案跟随扩展界面语言（与侧栏一致）。
    - **边界（v1，不许吹）**：只处理**顶层文档**的选区（`all_frames` 未开，跨域 iframe 里的划词看不到）；隐藏通道**不握有标签页控制权**，所以「搜索」只能靠 Agent 自己带的检索能力——它拿不到浏览器，也就不会动你正在看的页面。

### 跨页工作

因为工作区固定，用户可以在 A 页讨论、切到 B 页继续，让当前会话结合两页信息和本机文件做更复杂的事。换一个会话不会丢掉工作区里的页面快照，只是换一条聊天上下文。跨页的默认做法是 `openTab` 新开 http(s)，而不是 `navigate` 覆盖正在看的页（未保存编辑时扩展还会拦住覆盖）。`openTab` 一律**后台打开**，不会把用户正在看的页切走；Agent 需要用户看某个标签时走 `switchTab`（展示语义）。

### 状态持久化

再次打开侧栏时恢复：界面语言、主题偏好、权限模式、选中的 Agent 模式、会话列表、当前选中会话、每个会话的消息、上次选的模型、选中的 Agent、抽屉状态。`@` 菜单不持久化：标签页只列当前打开的标签，附件只列当前输入栏里的芯片。未发送的附件芯片和消息队列只活在当前进程。聊天不进云端：扩展存储是缓存，**权威副本在本机 `~/.opensider/ui-state.json`**，卸载重装扩展后仍能恢复。恢复不设体积门槛：镜像与扩展之间的状态传输在超过 Native Messaging 单帧上限时自动分片（每帧仍 <1MB），大历史照常落盘与灌回。用户删光本机 `~/.opensider` 才会真正丢掉侧栏历史。

## 决策记录

| 决策 | 选择 | 原因 |
|---|---|---|
| UI | 自研 ChatPane（lucide） | assistant-ui ExternalStore 的 `useAuiState` 与消息状态不同步，表现为发了没动效、也停不了 |
| 浏览器 | Chromium（Chrome / Edge / Brave 等） | Side Panel + Native Messaging；Firefox / Safari 不做 |
| 与 CLI 的连接 | 预编译 Go 二进制作 Native Host，按需拉起 `agent acp` | 扩展无法 spawn 进程；用户侧不装 Node；每个平台只发一份二进制 |
| 用户安装 | 把一段提示词发给自己在用的本机 AI Agent，由它按仓库 skill 执行 | 用户本来就在用能跑命令的 Agent，不该再让他们自己复制 shell 脚本；脚本也替不了「装扩展、按本机情况分步引导」 |
| 安装壳 | 删掉 `install.sh` / `install.ps1` 与 `install --local` 本地构建入口 | 跨平台分支（TLS / MOTW / arch 判定）维护成本高；壳能做的（下载、校验、注册）skill 都能做，且能把扩展安装和失败引导一起做完 |
| 半自动更新 | 只做版本检查（1h 缓存）+ 顶栏更新图标 + 可复制提示词的模态窗，不做后台静默自我更新 | Chrome 对 unpacked 扩展的热替换不稳，静默改写本机文件也不可解释；更新与安装共用同一套 skill |
| 需要适配器的 CLI（Claude / Codex） | `opensider install` 探测到 CLI 本体后 prefix-local 安装对应 ACP 适配器 | 官方交互式 `claude` / `codex` 都不带 ACP，各有一个官方包（`@agentclientprotocol/claude-agent-acp` / `codex-acp`）；缺适配器时自动装进 `~/.opensider/runtime/<agent>-acp` 并校验；没装该 CLI 跳过，没 Node 只提示。机制对两家通用（一份 `acpAdapterSpec`），以后再添同类 CLI 只需加一份 spec |
| 扩展安装包 | 只发 `extension.zip`，开发者模式 Load unpacked | 不上架；不发 CRX。skill 把它解到**用户选定的扩展目录**（安装时问，建议 `~/OpenSider`；不默认下载目录，也不许放进 `~/.opensider`），用户加载的就是这个目录，更新即覆盖它，zip 留在同级供用户复用 |
| 附件选文件 | macOS 混选；其它系统侧栏先选文件/文件夹 | Windows / Linux 系统框互斥，不自绘资源管理器 |
| 页面工具 | 内容脚本 + 工作区文件 RPC | 读和写都走同一通道，不必上 MCP、不必再开端口 |
| 填表定位 | 编号交互快照 + label/index + fillForm（参考 page-agent / browser-use） | 正文抽取看不到 placeholder；`innerText` 匹配会打到 label/标题，输入框本身填不进去 |
| Agent 操作光标 | 页面内浮动指针滑到目标再点按（参考 page-agent，不做全屏挡操作遮罩） | 用户要看见 Agent 在点哪里；全屏 mask 会挡住 `elementFromPoint` 和真人操作 |
| 页面自动化权限 | 白名单方法默认执行 | 逐步确认会打断自动化；系统页仍然隔离 |
| 页面截图 | 视口 / 元素 JPEG 写入工作区 | Native Messaging 有 1MB 上限，不能传原图；Agent 用 Read 看图片做视觉规划 |
| 能力发现 | 启动时写 AGENTS.md + tools.json | 会话 cwd 里第一眼就能看见全部方法 |
| 产物回传 | 工作区命令 `reportArtifacts`，Host 拦截后推侧栏 | 扩展看不见本机新文件；不另开 MCP；再次调用覆盖列表；打开位置找不到文件则该项标失效并写入会话 |
| 用户可见产物目录 | 工作区 `outputs/`（AGENTS.md + tools.json 引导；不拦截 Write/Shell） | 产物散落根目录会和协议文件混在一起；产品决定不限制 Agent 本地工具 |
| 工作区 | 全局单一目录 | 跨页连续工作，页面工具不跟会话走 |
| 会话 | 多会话 + 本机持久化 + 右侧抽屉分组 / 置顶 | 用户要新建 / 切换 / 置顶 / 保留历史 |
| 许可 | MIT（仓库根 `LICENSE`） | 公开仓库不明示许可，默认「保留所有权利」，别人法律上不能用 / fork / 再分发；MIT 最短、与周边生态兼容，也不强制衍生开源 |
| 删会话确认 | 非阻塞 popover（16px 安全边距） | 避免误删；`window.confirm` 会卡住侧栏，也不像现有弹出层 |
| Fork | 从某一轮 Agent 回复分出新会话 | ACP `session/fork` 目前不能指定消息；节点分叉用新会话 + 首条上下文 |
| 重新生成 | 同一会话丢掉该轮回复再跑 | 旧 ACP 历史含上次回复，所以换 `session/new` + 前文再 prompt |
| 改历史消息 | 点用户气泡带回输入框再发 | 替换该条、截掉之后，复用重新生成的 `session/new` + 前文 |
| 语言 | 英（默认）/ 中，本机记住 | 只要两种，默认英文 |
| 主题 | 浅色模式 / 深色模式 / 跟随设备，本机记住 | 抽屉设置下拉；token 化颜色保证两套对比度 |
| Agent 模式 | `agent`（完整本地工具） | 用户要求本地工具可用，且过程要在 UI 里看见 |
| 会话模式（Agent 自身） | 只显示 Agent 广告出来的模式；广告不足两项或没广告就不显示 | 各家 mode id 没有统一标准（裸字符串 / URL / 配置项三套机制），靠猜的映射只会把权限档误当模式 |
| 权限与模式的关系 | 拆成两个独立控件；权限档不再驱动 plan / build | 权限是我们的拦卡策略，模式是 CLI 自己的工作流；合成一个会让「选默认权限」把 OpenCode 推成 plan，用户既看不见也控制不了 |
| 模式适配策略 | 规范级通用发现优先；确有差异的才进显式适配层（按 CLI 收敛成可审计的小表），不适配就整体不显示 | 泛化能盖住多数 CLI；剩下的是各家怪癖，集中在一个适配层里好审、好删 |
| 模式图标 | 后端给出语义 kind，前端按 kind 映射 lucide 图标 | 分类要用 `_meta.kind` 与关键词，放在一处否则三处各猜一遍 |
| 附件 | 文件只传本机路径；元素只传 CSS selector | 扩展拿不到真路径；元素给 Agent 定位，不必上传 DOM |
| 图片预览 | Host 读字节、分片回传、侧栏 `blob:` | 扩展页拦 `file://`；Native Messaging 单帧 1MB，不能整图一次回 |
| 图片预览交互 | `react-zoom-pan-pinch` + 自绘顶栏（lucide） | 只要缩放/平移，不要为 Image 拉 antd；`react-photo-view` 自带 icon，和 lucide-only 冲突 |
| 提及 | contenteditable 芯片 + 当前打开标签 / 当前输入栏附件 | 要和文字混排，并让 Agent 读懂反序列化后的 tab / 路径 / selector；附件历史会和输入栏不同步 |
| 模型 | 各 CLI 的 list 命令 + ACP `configOptions` / `session.models` | 与当前 Agent 账号可选模型对齐，不写死目录；OpenCode 用 `opencode models` |
| Mermaid | `flowchart`/`graph` 用 dagre SVG；其它类型回退代码块 | mermaid 包太重且会污染 DOM、打字时重绘抖动；扩展 CSP 下 HTML 节点也常画不出来 |
| 标签/窗口 | `tabs.json` + `listTabs` / `switchTab` / `openTab` / `closeTab` / `moveTabsToWindow` | Agent 要先看见全部标签才能切换、新开、关闭或抽成独立窗口；走现有命令文件，不另开 MCP |
| 未保存编辑 | `getUnsavedChanges` + 跳转/关闭软拦截 | 有未提交内容时默认拒 `navigate`/`reload`/前进后退/`closeTab`；旁路查信息用 `openTab`；用户确认后才 `force` |
| 批处理脚本 | `runScript`（ISOLATED / MAIN） | 重复 DOM 操作一次跑完；先探索再写脚本；仅 http(s)，有超时与 JSON 结果限制 |
| Cursor 关流字 | 成功轮次吞掉 `WritableIterable is closed` | 这是 Cursor ACP 在内容流完后的可重试拆流，不是侧栏关 stdin；当失败展示会污气泡 |
| 会话绑定配对 | 每个 `session.new` / `session.use` / `session.fork` / `prompt` 带 `requestId`，`session` 回执按 id 一一配对 | 早期按到达顺序配对，任何一次响应缺失（连接错误、`session/load` 失败换新等）都会让之后所有绑定永久错位：旧任务的内容被写进新会话 |
| 无归属事件 | 丢弃（不落当前选中） | `localIdForAcp` 曾把找不到归属的 `update` / `turn.end` / HITL 落到「当前选中」会话，正是串戏的直接通道 |
| 浏览器工具事件归属 | Host 给命令标注唯一会话，SW 原样带回结果 | 没有标注时侧栏只能在「选中 / 第一个运行中」之间猜，多会话并行时工具调用会记到别的会话里 |
| 主按钮 hover | 强调色自身加深 / 提亮 + 涟漪 | 主按钮套 `--hover` 中性半透明覆盖会被读成禁用态；主按钮与次要按钮用两套 hover 策略 |
| Host 误伤兜底 | `cancel` / `model.set` 找不到目标会话就不动或只记 pending | 早期实现会「随便挑一个 prompting / 空闲的 runtime」下手，B 的停止会杀掉 A 的任务 |
| Agent 标签接管 | 锚点锁定 + 写操作自动接管；跨标签读写要用户批准 | 用户切标签不该带走 Agent 的目标；进入其它标签必须用户知情 |
| 无打扰默认 | `openTab` 后台开 / `switchTab` 只做展示 / 截图守卫式切换 | 用户视野是最高优先级资产；工作对象用 `tabId` 指定，不靠抢视图 |
| 收回与拒绝 | banner 一键收回；收回 / 拒绝后 10 分钟静默冷却 | 控制权必须随时拿得回来，同时不能被重复请求骚扰 |
| 互不影响前置件 | 光标后台瞬移（隔离世界 rAF 兜底）+ `autoDiscardable` 保护 | 主世界 activity shim 盖不到隔离世界；后台标签的 rAF / 回收问题必须先服务化 |
| 接管生命周期 | 回合结束自动归还 + 访问记忆（自建 / 已批准免再询） | 任务做完就该把控制权还回去；每回合重新问一遍同一张标签则是另一种噪音 |
| Skill 别名 | frontmatter `display_name` → 回退 `name` | `description` 实测 395–943 字符、是写给模型的触发说明，当别名读不了；`display_name` 是生态里已有的字段（本机 `水产市场`） |
| Skill 详情展示 | 高亮 / hover 时右侧二级面板给路径 + `description` 全文；窄侧栏折到列表下方 | `description` 是用户判断「这个 skill 干嘛用」的唯一材料，截断就失去意义 |
| Skill 芯片与发出 | 芯片显示 `/name`，正文最前发 `/name` + 附一段说明 | 别名只为好读，CLI 只认 `name`；ACP 里斜杠可能被当纯文本，附说明兜底 |
| Skill 插入位置 | 一律插到输入区最前面，多次选择在最左依次累积 | 斜杠前缀只有出现在最前面才会被 CLI 当 skill 调用 |
| Skill 扫描范围 | 六个全局目录（claude / cursor / codex / agents / cursor 内置 / stepclaw） | 只嗅探全局已装的；项目级与需要跑命令探测的成本高、会拖慢实时加载 |
| 工具栏功能钮 | ≥600px 平铺四个，<600px 收成 `+` 钮 | 窄侧栏放不下四个钮加两个下拉 |
